**Where the scanner runs.** Inside `refresh()`, after handler dispatch and after assembly — never
alongside discovery. This ordering is structural, not incidental: resolving a `D`-prefixed token
correctly requires knowing the resolved kind of the artifact it was found in, which does not exist
until dispatch has happened.

**`stripCodeForScanning(markdown)`.** Replace every fenced block and every inline span with an equal
number of space characters, so the returned string has exactly the same length as the input and every
offset in it indexes to the same position in the original. Scan the stripped string; report offsets
against the original. Handle fenced blocks first, then inline spans, so a backtick pair inside a fence
is not treated as a span. Add a test asserting that for a document containing both, every reported
offset slices the expected token out of the original content.

Skipping both is D-15's decision. This corpus is dense with code that trips an identifier pattern —
constants, hyphenated names, branch names — and prose mentions are what the linking requirements are
about. The accepted, known cost is that identifiers quoted in backticks are missed, which GSD authors
do constantly. If that proves too lossy in practice the narrower relaxation is to scan inline spans
while still skipping fences; do not revisit by scanning everything.

**The four schemes (D-13).** Export `ID_PATTERNS` keyed by scheme, covering exactly requirement ids,
decision ids, plan ids, and phase references. This is precisely the set the navigation requirements
consume. Everything else in GSD's nine-scheme inventory — threat ids, wave numbers, ledger integers —
is recorded only where it is already structured data in frontmatter and is never scanned out of
prose, because those are the schemes with no distinctive shape, where a bare integer would match any
number in any document.

Resolve the ambiguity between the decision and requirement patterns with an explicit precedence rule
rather than by expression ordering luck: a prefix of exactly one uppercase letter before the hyphen
is a decision; a prefix of two or more characters is a requirement. Encode that rule in a single
combined scanning pass that walks the stripped text once and takes the longest match at each position,
so a token can never be counted under two schemes. Constrain the plan-id pattern so a first numeric
group of four or more digits is rejected and a match whose surrounding run continues with another
hyphen-digit group is rejected; without both constraints an ISO date is indistinguishable from a plan
id.

**The mention record (D-16).** Each mention carries scheme, id, the artifact's path, the artifact's
resolved kind, a position holding a one-based line and a zero-based offset, and an excerpt of the
surrounding text clipped to the containing line and bounded in length. The position is what lets a
later phase deep-link to the right spot and what saves a later phase's snippet interface from
recomputing it; capturing it now avoids the eager-resolution-with-extra-failure-modes trap. Confirm
that positions survive the normalizing serializer unchanged — the serializer rewrites paths and
timestamps only, and an offset must not be touched.

**The index shape.** Key the index on scheme and id together, never on bare id. That is D-14's
instruction that identifiers are resolved within the context of the artifact type they were found in
and never as a single global namespace. Expose both the grouped map and a flat ordered list, sorted
deterministically by path then offset so goldens are stable.

**What the index must not become.** It reports that an id was mentioned in N places, with excerpts,
and nothing more. It must carry no authored text for a decision beyond what was literally copied out
of a mentioning artifact — no canonical-name field, no explanatory field, no justification field.
Decisions are not a file-backed entity in GSD and there is no registry file for them; anything beyond
what is textually recoverable would be a record the tool invented. Record that constraint on the index
type so a later contributor does not helpfully add such a field, and phrase the note in terms of the
rule rather than by listing candidate field names.

**Rebuild semantics.** `scanMentions` is a pure function of the parsed artifacts and returns a fresh
index; `refresh()` assigns it rather than merging into a previous one. Add a test asserting that after
two consecutive refreshes of an unchanged tree, the mention list for every id is identical in length
and content to the list after one refresh — an index that accumulates across refreshes is the exact
failure mode a future file watcher would surface.
