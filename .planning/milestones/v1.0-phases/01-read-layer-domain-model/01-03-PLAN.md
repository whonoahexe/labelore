**Structured-extraction depth (CONTEXT.md Claude's Discretion, item 1).** Resolved: extract
`ROADMAP.md`'s phase blocks fully in this phase, and carry the ASCII dependency diagram through as
opaque preformatted text.

Rationale: the phase's own success criteria 2 and 5 require a *complete* snapshot with *resolved*
cross-references. A phase's `requirementIds` and `dependsOn` cannot be resolved against
`REQUIREMENTS.md` unless they have first been extracted from `ROADMAP.md`'s `**Requirements**:` and
`**Depends on**:` lines. Deferring extraction to Phase 2 would leave Phase 1 unable to satisfy its
own criteria. The dependency diagram is the deliberate exception: `GSD-DOMAIN.md` confirms by direct
inspection of both the template and an independently-produced real roadmap that it is free-form art,
not a schema, so it is stored verbatim as a string and never arrow-parsed.

**Extracted in this phase:** phase number, name and slug; `**Goal**`; `**Depends on**` as a raw
string, not a parsed graph; `**Requirements**` as an array with brackets optional; `**Success
Criteria**` as a numbered list; the plan checklist as plan ID plus checked state; and the
`<details>`-wrapped milestone grouping, whose `<summary>` text is the milestone header.

**Not extracted, stored verbatim:** the ASCII dependency-shape diagram, and every prose section of
every artifact.

**Never derived:** progress and completion. Structured facts come only from `STATE.md`'s frontmatter,
`config.json`, and `ROADMAP.md`'s own explicit phase and plan checkbox syntax. Checkboxes in
`REQUIREMENTS.md`, `PATTERNS.md`, `RESEARCH.md`, or any prose checklist are never recounted into a
progress figure — the same visual pattern means three unrelated things across those files.

propagates and never discards the body.

| Boundary | Description |
|----------|-------------|
| Untrusted-shape YAML / JSON → typed handler | Every handler receives document content from a tree the tool did not author; a handler that trusts shape is a crash or worse. |
| Open-map `config.json` → snapshot object graph | DATA-03 mandates that unknown keys survive, which means attacker-influenced key names reach object construction. |
| Filename and directory names → grammar module | Names are attacker-influenced strings fed to regular expressions and to path composition. |
