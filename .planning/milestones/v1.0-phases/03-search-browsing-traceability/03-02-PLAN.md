`extractSnippets` works over the artifact's raw markdown body and the literal indexed terms MiniSearch
reported as matching. For each occurrence it records the offset; it prefers the longest matched term
when choosing which occurrence a window centres on, because the intact ID or path literal is always
longer than its split parts and that is what makes the snippet land on the ID match rather than a
generic word. Window size defaults to 160 characters, split evenly around the match; window boundaries
are clamped to the body and moved outward if they would fall inside a UTF-16 surrogate pair. Overlapping
or abutting highlight ranges inside one window merge into one range before being returned. The anchor
is resolved by scanning backwards from the window start for the nearest line matching a markdown ATX
heading, taking its text and running it through the extracted slug function so the fragment always
matches an id the renderer emits. Snippets for one row are returned ordered by `bodyOffset` ascending,
and the returned `matchCount` is the total occurrence count so the UI can show how many remain.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| raw markdown body → snippet window | Arbitrary corpus text, including literal HTML-looking strings, is sliced and returned over HTTP |
| snippet window → browser DOM | Corpus-derived text is placed into the page with a highlight applied |
| matched term → body scan | Search-derived strings drive an indexOf scan over every candidate body |

## STRIDE Threat Register (OWASP ASVS L1; unresolved high severity blocks completion)

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-03-02-01 | Tampering | snippet rendering in `search-page.tsx` | high | mitigate | Snippets render as escaped React text nodes split at merged highlight ranges, with only matched slices wrapped in a JSX `<mark>`; React's raw-HTML injection prop is asserted absent from the file by source grep. This surface has no rehype-sanitize stage between it and the DOM, which is why the escape-then-wrap ordering is non-negotiable. |
| T-03-02-02 | Denial of service | snippet extraction over large bodies | medium | mitigate | Matched-term location uses plain indexOf scans with a bounded window, never a constructed regular expression over corpus text; snippet count per row is bounded before extraction. |
| T-03-02-03 | Tampering | heading-anchor resolution | low | mitigate | Anchors are produced by the single extracted slug function the renderer itself uses, so a fragment can never point at an id the renderer did not emit. |
| T-03-02-04 | Information disclosure | snippet content | low | accept | Snippets echo the user's own local planning files back to the same user on localhost; no new data leaves the machine. |
</threat_model>
