# Quick 260916-o2o: Remove loading-state text, keep the skeletons, add a top bar loader

<objective>
Strip every visible loading headline from the app, keep (and complete) the skeleton vocabulary, and replace the shell's text-based route-transition fallback with a debounced top bar loader.

Purpose: loading screens currently shout a sentence at the reader for a few dozen milliseconds. Skeleton geometry already carries the "content is coming" signal; a thin top bar carries it for route transitions. The copy is noise.

Output: six pages with copy-free pending branches (two of them gaining skeletons they never had), one new `RouteProgress` component wired into the shell's single Suspense boundary, token-compliant CSS, and a source-text contract test that keeps the copy from creeping back.

Locked decisions (from `260916-o2o-CONTEXT.md`):
- Text-only screens (artifact, plan-pair) get a skeleton matching the existing skeleton convention, not just a text removal.
- The top bar loader is scoped to route navigation only — it replaces `app-shell.tsx`'s Suspense fallback. Per-page `isPending` branches keep their skeletons as the sole in-page loading signal and are NOT wired to the bar.
- Loader behavior (debounce timing, easing, height, placement) and the two new skeleton shapes are Claude's discretion; this plan pins them so execution is deterministic.
- `search-page.tsx`'s "Indexing…" branch is a distinct informational empty state with its own explanatory copy, not a skeleton-backed loading state — it is explicitly left alone.

Task-local requirement IDs:
- O2O-01: copy removal on the four already-skeletoned pages + re-seating the skeleton offset.
- O2O-02: real skeletons for artifact-page and plan-pair-page.
- O2O-03: the debounced top bar route loader replacing `PageLoadingFallback`.

No tracer task: all three tasks sit in one layer (client-side React + CSS). There is no stack to thread end-to-end, so the tracer-first shape would be theater here.
</objective>
