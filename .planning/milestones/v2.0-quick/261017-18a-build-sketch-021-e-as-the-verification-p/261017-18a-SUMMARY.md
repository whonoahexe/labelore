# Quick 261017-18a: the VERIFICATION page as a console rail, a gap-to-fix ledger and two boards

A VERIFICATION.md now opens on the verdict, not on a folded document. A sticky rail on the left names the phase, the status, the verified time, a big number (gaps that block the goal, checks left for a person, or the score when passed), the stat rows and the human checks as slips. The main column leads with the phase goal and the Gap to fix ledger, then the Truth board, the Requirement board, the numbered human steps, the anti-patterns, one "Also in this report" row of chips that open their section in Source, and the verifier footer. Source mode is the plain document. A report whose parse fails to produce the new data still gets the old folded-chapters page.

## What was built

- **Server side:** a new handler claims every VERIFICATION.md (phase, archived phase, live quick task, archived quick task) and adds the parsed report to the payload. The parser is line-scanned and fence-aware, capped, and a 1 MB body with a 200k-character line parses well inside the 250 ms bound. A throw only drops the new key.
- **Composer:** one pure module turns the frontmatter and the parsed report into the rail, the ledger, both boards and the rest. It maps each plan task to the gap it closes and each gap to the truth it concerns, reproducing the sketch's pairings (the synthetic report and studio-portal phase 4 are pinned task by task).
- **View:** one early return in the artifact page (no new kind branch); the old layout stays the fallback and is switched off when the board composes.
- **Dense golden:** changed only by the new key on the fixture's one VERIFICATION file (five copies).

## Discretion decisions, as built

- The page owns its rail and has no breadcrumb row, manifest lead or metadata disclosure in View mode, as the SECURITY page does. A parse warning shows as the shared chip in the rail.
- The board composes whenever the parsed report exists, even for a frontmatter-only report (the dense fixture shows status, a 2/2 frame and the Truths stat only).
- Phase numbers drop leading zeros ("Phase 6"). Quick tasks read "Quick verification · id". Titles drop "Phase N:", "Quick ... :" leads and "Verification Report" tails.
- Status tones: Passed complete, Gaps found missing, Human needed in-flight, anything else quiet.
- The Truths stat counts parsed truths (holding over total) and falls back to the score; the big number keeps the score.
- Human checks come from the body's numbered blocks (deeper or same level), else the frontmatter, titled from the bold list when counts match, else the test's first clause. A report marked resolved reads "Checked by a person" with a "Resolved" line and shows no slips and no count.
- "Also" chips: frontmatter items open Source at the top; sections open at their heading; an unresolved heading opens the top.
- Breakpoints: only the app's existing 62rem (rail stacks) and 42rem (three-column grids and ledger rows stack). Checked at 1440, 1024, 820 and 390 pixels; the three columns stay readable beside the rail at 1024.
- Motion: none added. Hover is a colour or border change; the jump flash is the only emphasis. The spot-check button sits above the list so the dialog opens at its top.

## Deviations from the plan

**1. [Rule 1 - Bug] Table cells with an odd number of backticks.** The shared row splitter toggles on every backtick, so one cell holding a double-backtick span swallowed the cells after it (labelore's own phase 5 report read a warning as info). The extractor uses its own splitter (a backtick run only opens a span when a run of the same length closes it). The plan said to use the shared splitter.

**2. [Rule 1 - Bug] "To check it" never appeared for labelore's phase 5 truths.** The sketch's 30-character match fails when the frontmatter item restates a truth with a dash where the table has a colon. Both sides are now folded to letters and digits before comparing. The plan's e2e expects this to match.

**3. Sideby phase 4 human-check titles.** The plan says "5 bold-list titles"; that report has no bold list. The titles are the first clause of each test (the first is "CALL-04 local speaking ring lights own avatar"), as the sketch's data does. The extractor reports no body checks for it, as pinned.

**4. Side-by-side fixes (old to new):**
- Tables stretched only to their content, because the app sets every table to display block; boards now use a real table at full width.
- Rail title was larger than the sketch; now the sketch size and weight.
- "Verified" read inline; now a label-left, value-right row.
- Quieter anti-pattern rows showed the whole path; now the file name only (blocker cards keep the full path).
- The spot-check dialog opened scrolled to the bottom; the "Open in source" button moved above the list.

**5. Kept as is.** Status chips and Also chips use the app's shared uppercase chip look rather than the sketch's mixed-case chips; the chip family stays consistent app-wide (F-05). The "Gaps found" chip is outline-only, as the shared chip is, where the sketch tints it.

**6. Tooling.** gsd-browser was not connected, so the captures and e2e ran through Playwright on /usr/bin/chromium (a temporary config outside the repo; the repo config is unchanged). The e2e removed the VERIFICATION entries from the folded-chapters spec, and with them the cover/glance smoke and the reference-preview test that only ran over VERIFICATION files.
