# Quick Task 261011-l07: Open remote projects over ssh Summary

The command `npm start -- sftp://rhgpu.taile250fc.ts.net/mnt/REACH/deid-template-studio` now opens the remote project instead of showing the "No such path" screen. Labelore copies the remote `.planning/` read-only into a temporary local folder using the system `ssh` and `tar`, reads that copy with the existing reader, and shows the `sftp://` address (not the temp folder) as the project location.

## What was built

- **Address parsing** (`src/cli/remote-target.ts`): understands `sftp://[user@]host[:port]/path`, `ssh://...`, and scp-style `[user@]host:/path` or `host:~/path`. A path ending in `/.planning` is accepted too, and `/~/...` means "under the remote home". Anything that is not a remote address falls through to the old local-path code unchanged. Bad hosts (such as ones starting with `-`), bad users or ports, query strings, control characters and passwords in the address are rejected before ssh ever runs; a password is shown as `***` in messages.
- **Read-only remote command**: the only thing sent to the remote machine is a fixed template that checks the path exists, is a directory, and has a `.planning`, then runs `tar -cf - .planning`. The path is single-quoted, `--` precedes the host, and both processes are started from argument lists with no local shell.
- **Mirror and lifecycle** (`src/server/remote-source.ts`): ssh output is piped into a local `tar` that unpacks into a fresh `labelore-remote-*` folder. Refresh pulls into a new folder first and only then deletes the old one, so a failed refresh leaves the last good view serving. The mirror is deleted on a failed pull, server close, normal exit, Ctrl-C and SIGTERM.
- **Guarded temp folders** (`src/planning-fs/local-fs.ts`): create and remove helpers kept in the one file allowed to use the filesystem. Removal refuses anything that is not a direct child of the OS temp folder with the `labelore-remote-` prefix.
- **Server wiring** (`src/server/index.ts`): remote addresses are routed before local path resolution; the smoke line now reports the load status; a remote start prints an extra line saying the project is mirrored read-only and Refresh pulls it again.
- **Failures** map onto the three existing error screens with the ssh error text included: unreachable host, timeout, missing path or file-not-directory show as path-not-found; login or host-key failure and an unreadable folder show as permission-denied; no `.planning` shows as not-a-gsd-project.

## Verification

- Live, read-only against rhgpu.taile250fc.ts.net: smoke prints `load status: ok` for the sftp address and for the scp-style address with a `.planning` suffix; `/api/dashboard` answers ok; `/api/presentation` reports the sftp address as the root path; `POST /api/refresh` answers `refreshed: true`; after SIGTERM no `labelore-remote-*` folder remains.
- Live failure checks: a missing remote path gives path-not-found, `/etc` gives not-a-gsd-project, an unresolvable host gives path-not-found, and an address with a password is rejected without contacting anything.
- New tests: 41 for parsing, quoting, command construction and failure mapping; 12 for the mirror lifecycle, the guarded removal, Refresh through the app, and the real ssh-to-tar pipe using local stand-ins. The filesystem-boundary test, typecheck and lint all pass. No dependency was added.
