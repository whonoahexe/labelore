<objective>
Build sketch 018's winner, **B: Scorecard — hexagon radar + pillar inspector**, as the UI-REVIEW page view. A UI-REVIEW.md is a retroactive 6-pillar audit whose body is mostly passing evidence; the view answers "did it pass, what should I fix, where were points lost, and can I trust how it was audited": a radar of the six scores beside the verdict, the fix pins and the method chips, then a pillar tab bar and an inspector that puts each pillar's issues and fixes before its passes, with the back matter folded at the end.

Purpose: UI-REVIEW is the next type in the per-type view loop (DISCUSSION-LOG, CONTEXT, RESEARCH, PATTERNS, UI-SPEC and UAT are built). Today it renders through the generic promoted-section view with a four-fact Score block.

Output: a server-side UI-REVIEW extractor and handler, a pure composer, the view components and one delimited CSS block, wired through the view-registry seam exactly as UAT is; unit, corpus, contract and static-markup tests; a narrow e2e spec for post-merge; gsd-browser side-by-side evidence against the sketch on all five sketch docs, with every deviation fixed or recorded.
</objective>
