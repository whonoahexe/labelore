<objective>
Build sketch 020's winner, **D: B head + C body**, as the SUMMARY page view. A SUMMARY.md records what one plan or quick task shipped. Today it renders through the generic promoted-section view, which repeats itself (key-files vs Files Created/Modified, key-decisions vs Decisions Made, duration vs Performance) and buries what shipped. The view answers four questions: where it stands (status, date, duration), what shipped (Outcome), how the run went (task timeline with deviations on their task), and what proves it (Proof). Then it shows decisions, patterns and lineage once each, and names what it leaves to Source.

Purpose: SUMMARY is the next type in the per-type view loop (DISCUSSION-LOG, CONTEXT, RESEARCH, PATTERNS, UI-SPEC, UAT, VALIDATION, SECURITY and UI-REVIEW are built). The sibling item 261006-iz6 builds the PLAN page in parallel.

Output: a server-side SUMMARY extractor wired into the existing SummaryHandler (now also covering quick summaries), archived-requirements parsing so requirement IDs can preview their text, a pure composer, the view components and one delimited CSS block, wired through the view-registry seam. Also unit, corpus, contract and static-markup tests, a narrow e2e spec for post-merge, and gsd-browser side-by-side evidence against the sketch on all five sketch docs plus six harder corpus summaries, with every deviation fixed or recorded.
</objective>
