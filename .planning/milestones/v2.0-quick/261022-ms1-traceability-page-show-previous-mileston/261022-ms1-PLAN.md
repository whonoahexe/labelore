# Quick 261022-ms1: Traceability page shows previous milestones' requirements for reference

<objective>
Between milestones, `/gsd-complete-milestone` moves the root `.planning/REQUIREMENTS.md` to
`milestones/vX.Y-REQUIREMENTS.md`, so the traceability page shows a 0% headline over nothing and a bare
empty state. This task adds a "Previous milestones" history section that shows each archived
milestone's requirements, read-only and resolved against that milestone's own archived phases. When
there are no current requirements, it replaces the misleading empty summary with a short note and opens
the newest milestone.

Purpose: the user's cinedise-portal session (and labelore's own `.planning/`, which has no root
REQUIREMENTS.md and archives v1.0 and v1.1) shows an empty traceability page between milestones.
Output: a new view-model field and page section, with presentation and contract tests.

No read-layer change is needed. `RequirementsHandler` already parses `milestone-root`
`vX.Y-REQUIREMENTS.md` files (quick-261006-iz7), and `toProjectPresentation` already passes every
artifact through as an `ArtifactDto` with `structured.items` and `structured.traceability`. Archived
milestones and their phases are already in `presentation.milestones` (`archived: true`, `version`
set). The projection reads only the presentation DTO, the same way `roadmap.ts`'s `milestoneRecords`
reads MILESTONES.md, so the reader boundary from CLAUDE.md holds.
</objective>
