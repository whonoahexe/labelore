<objective>
Teach the discussion-log parser a fourth tolerated question shape, S4. In S4 a `##` topic holds one compact table with header `| Question | Options | Selected |`. Each row is one question, the options sit in a single cell separated by " / ", and Selected is free text. The compact-table logs agents improvise then show every question, with the answer the user picked. Today they show "0 decided".

Purpose: A real Phase 2 log written in this layout currently parses into 4 open, option-less questions, one per topic heading. The page reports 0 decided, which goes against the project's core value of knowing where the work stands without reading files by hand. GSD's official template stays the S2 shape. S4 is an additional tolerated shape, and S1/S2/S3 behaviour must not move.

Output: S4 support in src/planning-repo/handlers/section-projection.ts, an end-to-end layout test in test/web/discussion-log-corpus.test.ts, and an S4 parser test matrix in test/section-projection.test.ts.

Planner discretion, recorded here. These refine the orchestrator's required behaviour and narrow none of it:
- Exact matches win over prefix matches. For Selected "Both" with options "Both / Both + extra", the plain rule would find two candidates and fall back to settled; with this refinement the exact option is picked.
- A 'claude' row still runs option matching. A literal "You decide" option therefore gets chosen/chosenIndex, the same as an S1/S2 ✓ on a "You decide" row. userChoice holds the Selected text, the same as S3's table-less inline "you decide". When nothing matches, settled stays null.
- `Other:` with nothing after it resolves to 'open', because there is no answer text to show.
- A row whose cells are all empty is not a question and is skipped. Any other row is kept, so no question is dropped (JXP-05).
- Every qualifying table run in a section contributes rows. A table run that does not qualify counts as leftover.
</objective>
