# Phase quick-261023-61k Plan 01: Todo page as a lifecycle Summary

Every todo file now opens on a page that tells its story: a strip of Noted, Captured and Closed (or Now while open), then one numbered spine with the notes it came from, the todo itself, and how it closed or how long it has been open.

## What the page shows

- **An open todo** (for example the retry-queue one): a large title, a chip row (Pending, a severity square carrying the written word, the area), and the strip: Noted shows "No note", Captured shows the date and weight, Now shows "Open 11 days" and "Waiting in todos/pending/". Under it: Captured as a todo (the problem beside the solution, a files box with line ranges such as L88–140), then a dashed "Open 11 days. Nothing has closed it yet." A checklist todo adds "— 0 of 4 items checked."
- **A closed todo** (crop and round profile photos): Noted lists each source note as a card (date, how it was found, its text folded with Unfold / Fold, and "Open note" to the note's own page); Captured shows problem beside solution and five files; Closed shows the resolution in a tinted box, the quick task ("quick 261022-m25 · 22 Oct 2026") and any commit chips. A todo closed by a leading "Closed ..." callout (chrome drift) shows that callout, three commit chips, and a quick-task link to that task's summary page.
- **A todo with no notes**: the Noted step is plain text ("No note · Captured straight as a todo"), there is no Noted stage and the spine starts at 1 with Captured.
- **A todo with nothing below its frontmatter**: "Nothing below the frontmatter — the title is the whole todo." A done todo with no resolution says "Moved to todos/completed/ with no resolution written."
- Note references in the text (`[[slug]]`, `notes/....md`) become in-app links to the note's page; inside backticks they stay code, and a link to something that is not a note stays plain text. The page ends with one "Also in this file" chip row (Frontmatter opens Source). Source mode is the plain page.

## Decisions as built

- **Todos get their own kind from where they sit.** Every markdown file under `.planning/todos/` is a todo (add-todo and note promotion use free-form names, so no filename can recognise them). The location stays `other`, so the tree, search grouping and goldens did not move.
- **Status is the folder**: `pending/` is Pending, `completed/` or `done/` is Done, anywhere else is Unfiled ("Filed outside todos/pending/"). A frontmatter `status:` is shown nowhere.
- **Dashboard colours now match the page.** The On deck todo squares use the same two severity colours as the page (High `--missing-fill`, Medium `--in-flight-fill`) instead of `--destructive` and `--primary`, because those match every other page's severity scale and `--destructive` is reserved for read failures. Two CSS lines and one design-language sentence; reversible.
- **Times follow their zone**, unlike the debug page's literal reading: /gsd-note writes local wall time with no zone, add-todo writes a UTC instant, and read literally the note would appear to precede the todo it created on the same day. A date-only value or a midnight-UTC stamp is a day with no time; a zone-less date-time is shown as written; a stamp with Z or an offset is shown in the viewer's time zone. "Open N days" counts calendar days in that zone.
- **One shared todo-to-note relation** (`src/presentation/todo-notes.ts`) answers both "the notes this todo came from" and "the todos this note became", server-side, for the NOTE page item (261023-61l) to use. A note is found four ways (listed, wiki link, mentioned, promoted word for word); when found several ways it keeps its first position and takes the strongest way.
- The closing quick task links to its summary (else plan) page when the project holds that file; the strip step shows it as text because a step is itself a button.
- Nothing in the file is dropped: prose before a Problem or Goal section becomes a "Details" fold (the sketch silently dropped it).
