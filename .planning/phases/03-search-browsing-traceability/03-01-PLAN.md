Create `src/server/search-index.ts` following `src/server/artifact-index.ts`'s exact shape — a `build`/`create` factory over a passed-in `ProjectSnapshot`, returning a frozen object exposing read methods, importing no Node filesystem or path module. Export: `SearchDocument` (fields `id`, `path`, `kind`, `title`, `frontmatterText`, `body`), `SearchHit` (fields `path`, `title`, `kind`, `url`, `phaseKey`, `milestoneKey`, `score`, `matchedTerms`), `SearchIndexState` as a discriminated union on `status` with members `building`, `ready` (carrying `index`, `documents`, `builtAt`) and `error` (carrying `message`), `createSearchIndexState()` returning `{ state(), buildFrom(snapshot) }`, `buildSearchDocuments(snapshot)`, `tokenizeSearchText(text, field)`, `processSearchTerm(term, field)`, `searchIndex(state, query)`, and `MAX_QUERY_LENGTH` set to 256.

`tokenizeSearchText` splits on Unicode whitespace and a punctuation set that deliberately EXCLUDES `-`, `/` and `.`, so an ID token and a path token survive tokenization intact. `processSearchTerm` trims leading and trailing separators, lowercases, and — when the trimmed token matches the ID-or-path shape — returns an array whose first element is the intact lowercased literal followed by every split part longer than one character; otherwise it returns the single lowercased term. The ID half of that shape test reuses the exact requirement-ID grammar already established in `src/planning-repo/mentions.ts`'s `ID_PATTERNS.requirement`; the path half requires at least one `/`. Both patterns must satisfy the ReDoS rule that file already states — anchored, bounded quantifiers, no nested unbounded groups — and must carry the same style of justifying comment naming this plan's threat id.

`buildSearchDocuments` reads only `Artifact.body`, `Artifact.title`, `Artifact.kind` and the artifact's frontmatter keys and scalar values flattened into `frontmatterText`. For a `plan`-kind artifact, strip the pseudo-XML wrapper tag lines recognised by `src/rendering/plan-segments.ts` from the indexed body before indexing so those tags never become searchable terms; the artifact's own text between tags is preserved verbatim. Never call the artifact renderer.

`createSearchIndexState` starts at `{ status: 'building' }` and, inside `buildFrom`, schedules the MiniSearch construction and `addAll` on a `setImmediate` callback, assigning the `ready` state only after `addAll` returns and capturing a thrown error as `{ status: 'error', message }`. Search options are `prefix: true`, `fuzzy: false`, `combineWith: 'AND'`, with field boosts `title: 3`, `frontmatterText: 2`. `searchIndex` rejects a query longer than `MAX_QUERY_LENGTH` by truncating to that length before searching, maps each MiniSearch result to a `SearchHit` whose `url` comes from `buildArtifactUrl(owningPhaseIdentity ?? null, path)` and whose `matchedTerms` is `Object.keys(result.match)`, and sorts by score descending then `path` ascending.
