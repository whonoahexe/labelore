<assumption_delta_decision>
Detector: pluralization (one project per run becomes several).
Primary noun: the project registry entry, keyed by its persisted slug, owning one ProjectRuntime.
Decision: promote. ProjectRuntime and the slug-keyed registry become the only way the served app
reaches a snapshot. createApp(source) is demoted to a thin, guard-free, test-only wrapper that
mounts the very same createProjectApi with one fixed runtime at /api, so the existing server tests
keep running without a second set of handlers.
Invariant tests (accepted, built in this plan and 08-04): (1) route-set equality, every project API
route is reachable under /api/projects/:slug; (2) per-slug isolation, every parameterless GET route
answers each project's own data; (3) 08-04 adds a source scan that startServer constructs the
registry app and never createApp.
</assumption_delta_decision>

<objective>
Split today's single-project closure into one ProjectRuntime per project behind a slug-keyed
ProjectRegistry, serve every existing handler once at /api/projects/:slug/*, list projects cheaply
at GET /api/projects, and put the request guard (SEC-05, D-18, D-20) in front of all of it before any
write endpoint exists. The runtime count is bounded by an LRU of five (Claude's discretion,
research Pattern 4).

Purpose: this is the server backbone every later plan builds on: the settings file (08-03), the
server start (08-04), the scan (08-06) and the whole client switch (08-05, 08-07, 08-08).
Output: project-runtime.ts, project-api.ts, project-registry.ts, registry-api.ts, request-guard.ts,
the shared project-list.ts DTO, the legacy createApp wrapper, and their tests.
</objective>
