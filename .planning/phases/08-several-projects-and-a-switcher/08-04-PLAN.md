<objective>
Give Labelore its own settings file (PLAT-06, D-19): the one write path in the program lives in a
second, explicitly allow-listed node:fs importer with a fixed path, writes atomically, re-reads
before every change, and survives corrupt, newer and hand-edited files (D-12); every test run gets
a throwaway settings directory (D-09). 08-16 builds the remembered project list on this store: add
(PLAT-07, D-17), forget (D-10), the open stamp (D-08), CLI remembering (D-09, D-22), last-opened
order (D-04), PROJECT.md titles (D-21) and the proof that the file never lands inside a target
project (SEC-05, D-19).

Purpose: persisted slugs are what keep bookmarks working across runs (PLAT-08, D-11); the pure model
and the store are the only code that reads or writes that file, and every later plan reaches it
through 08-16's registry.

and their tests.
</objective>

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-08-11 | Tampering / Denial of service | torn or concurrent settings writes | medium | mitigate | temp file in the same directory with flag wx, then rename; re-read before every change; failure leaves the old file and no temp file |
