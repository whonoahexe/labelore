<objective>
Put the request guard (SEC-05, D-18, D-20) in front of every /api route of the registry app before
any write endpoint exists: a Host allowlist on every request, GETs included, so a DNS-rebinding
page cannot read any project; same-origin proof and a JSON content type on every mutating
request; an opt-in LABELORE_ALLOWED_HOSTS for a tunnel or reverse proxy; and a refusal test that
enumerates the registered routes so a route added later is covered or fails.

Purpose: 08-04 adds the first write endpoints (add, forget, open) and 08-07 the scan; both land
behind this guard and are covered by its route-enumeration test without edits.
Output: request-guard.ts, its registration in registry-api.ts, the guarded-request test helper,
the guard matrices, the enumeration refusal test and the moved refresh tests.
</objective>

Export createRequestGuard(policy): MiddlewareHandler that answers 403 { error: 'refused', reason: 'host' } when the Host header is not allowed; then, for every method other than GET and HEAD, treats the request as same-origin only when the Sec-Fetch-Site header is present and equals same-origin, or, when that header is absent, when an Origin header is present and new URL(origin).host lower-cased equals the lower-cased Host (an unparsable Origin or the literal null is not same-origin); otherwise 403 { error: 'refused', reason: 'cross-site' }; then requires a Content-Type matching /^application\/json\b/i, else 415 { error: 'refused', reason: 'content-type' }. ## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| any web page in the user's browser to 127.0.0.1 /api | Cross-site requests and DNS-rebinding requests reach the local server |
| a tunnel or reverse proxy to the local server | A public host name arrives in the Host header |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-08-01 | Information disclosure | every /api GET through DNS rebinding | high | mitigate | createRequestGuard refuses any Host outside 127.0.0.1/localhost on the server's port (plus exact opt-in hosts) before a route runs; table test over the enumerated route set |
| T-08-02 | Tampering | POST /api/projects/:slug/refresh and every later mutating route | high | mitigate | same-origin proof required (Sec-Fetch-Site same-origin, else Origin host equal to Host), absent proof refused, JSON content type required so a cross-site form cannot send one; refused requests proven side-effect free |
| T-08-03 | Spoofing | Origin comparison | medium | mitigate | the Host allowlist runs first and Origin is compared with the validated Host, never with c.req.url |
| T-08-04 | Tampering | sandboxed sketch scripts (opaque origin) | medium | mitigate | Origin null is refused on every mutating route; test case in request-guard.test.ts |
| T-08-08 | Elevation of privilege | LABELORE_ALLOWED_HOSTS misconfiguration | low | mitigate | opt-in, exact host matches only, wildcard and malformed entries dropped by parseAllowedHosts |
