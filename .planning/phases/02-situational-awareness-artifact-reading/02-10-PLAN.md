<objective>
Close UAT gaps G-01, G-11 and G-06 in the rendering pipeline: make PLAN wrapper segmentation
unconditional so unrecognised tags stop leaking as literal text and stop destroying the markdown
list structure inside them, and lock the syntax theme the tester rejected to the pair the UI-SPEC
now names.

Purpose: `02-UAT.md` recorded `</execution_context>`, `<read_first>` and `<scope_note>` rendering
as visible garbage text on every real GSD `PLAN.md`, with `<read_first>` list items collapsing into
one run-on paragraph. Both trace to a single early-return in the segmenter that skips any tag
outside a fixed recognised set. The UI-SPEC's revision replaces that gate with an unconditional
generic fallback, because a recognised set is a guarantee of recurrence on every tag GSD's grammar
adds next — which directly contradicts the project constraint that unknown artifact input must
degrade rather than break.
Output: a rendering pipeline in which recognition decides presentation only, never whether a
wrapper becomes a section at all, plus the committed suite that holds it there.
</objective>

## Planner assumptions and declined items (explicit, not silent drops)

**Planner decision extending the UI-SPEC.** The contract states that no tag name should fall through
to raw text. Taken literally that would put HTML void elements (`br`, `img`, `hr`) on the segmenter's
open stack with no possible close, emitting a spurious malformed warning at end of body for any PLAN
that authors one. Task 1 therefore introduces `HTML_PASSTHROUGH_TAGS`. This is recorded here as an
extension of the contract rather than an implementation detail, because it is the one place this plan
does not do what the contract says on its face. The rationale is that HTML's element set is closed
and GSD's wrapper vocabulary is open, so this is the opposite polarity from the defect being fixed.
Rated `reversible`: one constant, one consumer.

**Edge-probe rows this plan owns (§A lift from `.edge-coverage-fallback.json`).** Seven classified
rows are auto-resolved *(explicit)* and authored as plain `must_haves.truths` strings above:
READ-03 `empty`, READ-03 `encoding`, READ-01 `adjacency`, READ-01 `empty`, READ-01 `ordering`,
NAV-04 `empty`, NAV-04 `encoding`. Each has a defensible mechanical acceptance criterion, so none
was demoted to `backstop`. Seven surfaced = 7 authored + 0 flagged for this plan's share.

**UI-SPEC `## UI Considerations` lift, this plan's share.** E15's eight rows: `empty`, `error`,
`populated`, `partial`, `zero-one-many` are authored as explicit truths above; `loading` is carried
as the UI-SPEC's own dismissal (inherited from E7 — the artifact document is one query and a section
has no independent loading state) and is recorded here rather than dropped; `overflow` and
`long-text` belong to the stylesheet and are owned by plan 02-12. Eight surfaced = 5 authored here,
1 dismissed with the reason restated, 2 handed to 02-12 by name.

**Prohibition probe, this plan's share.** Stage 1 over-produced four candidates for READ-03/READ-04;
Stage 2 kept one (the recognised-set-extension prohibition authored above, descriptor-less). One
