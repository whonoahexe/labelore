## Spacing Scale

**Gap identified.** The implementation does **not** follow a discrete 8-point token scale. It uses
fluid, purpose-fit `rem` values throughout (`0.65rem`, `0.82rem`, `0.85rem`, `1.15rem`, `1.25rem`,
`clamp(1.25rem, 3vw, 2rem)`, etc.) chosen per-component for visual rhythm rather than snapped to a
4px grid. This was a deliberate authoring choice for a typography-led, editorial layout (Sera style)
and is consistent with itself, but it is **not** the standard GSD 4/8/16/24/32/48/64 contract.

**Retroactive contract (documents actual state; not a redesign):**

| Token | Value | Usage (as implemented) |
|-------|-------|-------------------------|
| xs | ~0.4–0.45rem (6–7px) | Icon-to-label gaps (`.eyebrow`, `.status-chip`, `.text-link`) |
| sm | ~0.65–0.85rem (10–14px) | Compact internal padding (chips, wave-band rows, metadata panels) |
| md | ~1–1.25rem (16–20px) | Default card/panel padding, list-item vertical rhythm |
| lg | `clamp(1.25rem, 3vw, 2rem)` (20–32px) | Section padding on major panels (`.immediate-work`, `.attention-panel`, `.milestone-flow`) |
| xl | `clamp(1.5rem, 4vw, 3.5rem)` | Document canvas padding, page-stack horizontal padding |
| 2xl | `clamp(2rem, 5vw, 4.5rem)` | Page-intro / hero vertical spacing |
| 3xl | `clamp(2rem, 5vw, 5.5rem)` – `7rem` bottom | Page-stack top/bottom padding |

**Exceptions (forward guidance for Phase 3/4 additions to this surface):** New spacing decisions in
later phases on this same visual surface (roadmap, dashboard, artifact reader) should snap to
4px-multiple values (4, 8, 12, 16, 24, 32, 48, 64) wherever a new value is introduced, to begin
converging the surface toward the standard scale — but do **not** retroactively rewrite the passing,
already-shipped Phase 02 CSS as part of this contract capture. Icon-only touch targets (`icon-sm`
button = 2.25rem/36px, `icon` = 2.5rem/40px) are an accepted exception to any 44px minimum, consistent
with a desktop-first local dev tool; no mobile-specific touch-target audit is in scope for Phase 02.

## Typography

**Gap identified.** The implementation uses fluid `clamp()` typography with many distinct sizes
(at least 15 unique `font-size` declarations across the surface) rather than a discrete 3–4-size
scale. This is intentional editorial/display styling (large hero numerals, uppercase mono labels,
long-form reading body) but diverges from the standard GSD "declare exactly 3–4 sizes" contract.

**Retroactive contract — four representative anchor roles, each with its real clamp range:**

| Role | Size | Weight | Line Height | Font | Notes |
|------|------|--------|-------------|------|-------|
| Body | 0.94rem–1.02rem fluid (`clamp(0.94rem, 1.4vw, 1.02rem)`); 0.77–0.86rem for secondary/meta text | 400 (regular) | 1.5–1.75 (`.artifact-document` = 1.75; secondary meta text = 1.5–1.55) | `--font-sans` (Space Grotesk) | Reading body inside `.artifact-document`; long-form prose capped at `76ch` measure |
| Label | 0.6rem–0.78rem (`.eyebrow`, `.status-chip`, table headers, `dt` labels) | 600–650 (semibold) | 1.15–1.3 | `--font-heading` (JetBrains Mono) | Always uppercase, `letter-spacing: 0.04em–0.13em` — this is the app's "chrome" voice: nav, chips, badges, breadcrumbs |
| Heading | 1.05rem–2.7rem fluid (h2/h3/`.roadmap-phase-header h3`/`.artifact-document h2/h3`) | 600 | 1.2–1.25 | `--font-heading` (JetBrains Mono) | Section and document headings; `letter-spacing: -0.035em to -0.065em` (tight, display-like tracking on mono) |
| Display | 2rem–6.6rem fluid (`.position-copy h1`, `.formal-progress-value strong`, `.artifact-heading h1`) | 500–600 | 0.8–0.98 (very tight) | `--font-heading` (JetBrains Mono) | Hero numerals and page-title treatment; letter-spacing as tight as `-0.08em` |

**Exceptly declared weights:** only two weights are used anywhere in the surface — **400 (regular,
body prose)** and **600 (semibold, everything else: headings, labels, chips, buttons)** — plus one
outlier, **650/700**, used for a small number of emphasis elements (`.requirement-list a`,
`.plan-section-label`, `Popover` open-action button). Treat 600 as the standard non-body weight and
650/700 as an accepted micro-emphasis exception, not a third general-purpose weight.

**Forward guidance:** new typography introduced on this surface in later phases should reuse one of
the four anchor roles above rather than inventing a fifth size tier.

## Color

The palette is the Studio Portal `base-sera` oklch token set, unmodified in structure, both themes
present (`:root` = light, `.dark` = dark). Radius is squared per UI-01: `--radius: 0.625rem` feeding
`--radius-sm/md/lg/xl/2xl/3xl/4xl`, and the actually-applied corner style throughout the CSS is **0
(fully square)** — the button/component primitives use `rounded-none` explicitly (see
`buttonVariants` in `button.tsx`), overriding shadcn's default rounded corners. This is UI-01's
"squared-corner convention" made concrete: **radius tokens exist in the theme but are not applied to
any implemented Phase 02 surface** — every card, panel, chip, and button renders with hard corners.

| Role | Value (light / dark) | Usage |
|------|------------------------|-------|
| Dominant (60%) | `--background`: `oklch(1 0 0)` / `oklch(0.145 0 0)` | Page background, `.app-shell`, `.roadmap-phase-body`, document canvas base |
| Secondary (30%) | `--card` `oklch(1 0 0)`/`oklch(0.205 0 0)`, `--secondary` `oklch(0.967 0.001 286.375)`/`oklch(0.274 0.006 286.033)`, `--muted` `oklch(0.97 0 0)`/`oklch(0.269 0 0)`, `--sidebar` `oklch(0.985 0 0)`/`oklch(0.205 0 0)` | Panels (`.immediate-work`, `.attention-panel`, `.metadata-panel`, `.wave-band`), code block background (`pre` uses `--secondary`), table header row, wave-stack background |
| Accent (10%) | `--primary`: `oklch(0.553 0.195 38.402)` light / `oklch(0.47 0.157 37.304)` dark (warm orange/amber hue) | **Reserved for:** primary CTA (`Button variant="default"`), the "Open" action in reference previews, active nav-link underline + brand mark background, `.immediate-work` top border + hover-arrow icons, `status-chip[data-tone="active"/"complete"]`, `.roadmap-marker` on complete phases, document links (`a` inside `.artifact-document`), heading-copy icon on hover/focus, `.eyebrow` label text, `.milestone-version`, `.requirement-list strong`, blockquote left border, table `::selection` tint. **Never** used for body text, panel borders, or default (non-active) chrome. |
| Destructive (second semantic) | `--destructive`: `oklch(0.577 0.245 27.325)` light / `oklch(0.704 0.191 22.216)` dark | **Reserved for:** the formal-vs-disk discrepancy callout, the shell-level snapshot-error notice, `.attention-list li[data-type="discrepancy"]`, `.blocked-by` labels, `.plan-segment-warning` / `.artifact-empty` degraded-render borders. This tool is read-only, so destructive is never a delete/confirm action color — it is exclusively a **degradation/discrepancy signal color**, which is the correct semantic use for a read-only tool. |

Border/ring/input tokens (`--border`, `--ring`, `--input`) are the neutral grayscale set and are used
pervasively as 1px hairline dividers — the visual language leans on hairline borders + hard corners +
generous whitespace rather than shadow/elevation for most surfaces; the two intentional shadow
exceptions are `.immediate-work` and `.document-canvas`, which use an offset hard-edge box-shadow
(`0.65–0.7rem 0.65–0.7rem 0 color-mix(...)`) as a deliberate "stacked card" accent, not a blur shadow.

## Copywriting Contract

Read-only tool: **there are no destructive actions anywhere in this phase's UI** (per project
constraint — the tool cannot write). The Copywriting Contract below documents copy as implemented.

| Element | Copy |
|---------|------|
| Primary CTA | **"Open"** (`.reference-preview-open`) — the sole persistent-intent action in this phase; deliberately minimal per D-14/D-15 (preview-first, single explicit escape hatch to the full page). Icon: `ArrowUpRight`. |
| Empty state heading (per-surface) | "No dependency-ready work is reported in the active milestone." (dashboard next-up) · "No discrepancy, blocker, dependency wait, or human gate needs attention." (needs-attention) · "No success criteria authored." / "No requirements mapped." / "No plans are present for this phase." (roadmap phase detail) · "No archived milestones are present in this snapshot." (history) · "This milestone has an authored identity but no phase rows yet." (empty milestone) · "Empty document" (artifact body) · "Empty list" / "Empty object" (frontmatter metadata panels) |
| Empty state body | Each heading above is self-contained (states the absence directly, in the domain's own vocabulary — "dependency-ready," "human gate," "phase rows") rather than a generic "Nothing here yet." No separate "next step" line is appended, because this is a read-only observational tool: there is no action the empty state should prompt the user to take. |
| Error state | "The project snapshot did not respond." / "Dashboard request failed" / `{dashboard.error.message}` (dashboard) · "The roadmap could not be loaded." / "Request failed" / `{roadmap.error.message}` (roadmap) · "GSD Lore could not read this project." / "Local project load failed" / `{view.loadStatus.message}` (project-level load failure) · "The shell could not refresh its snapshot metadata. Page-level data may also be unavailable." (shell-level degraded banner) — pattern is consistently: **plain-language headline → labeled sub-panel → the raw underlying message string**, never a bare stack trace. |
| Destructive confirmation | Not applicable — no destructive actions exist in this read-only tool. The `destructive` color token is reserved for discrepancy/error signaling only (see Color table), never for a confirm-delete affordance. |
