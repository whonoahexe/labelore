the read layer: a user-supplied project path becomes a canonicalized root, that root is read
through the `PlanningFilesystem` boundary, its `.planning/` tree is discovered, dispatched to a

<decisions_resolved_by_this_plan>
CONTEXT.md left two areas to the planner's discretion. Both are resolved here and are binding
for the rest of the phase.

**Path targeting mechanics (TGT-01 / TGT-02).** Positional CLI argument, not an environment
variable. Both a project root and a path pointing directly at a `.planning/` directory are
accepted. The raw argument is tilde-expanded, resolved to absolute, then canonicalized with
`realpathSync` exactly once at startup; the canonicalized root is the only path any later code
sees. A symlink supplied *as* the root argument is followed without objection. A symlink
encountered *inside* the tree during the walk is followed only while its resolved target still
lies within the canonicalized root; otherwise its content is refused. Each failure mode gets one
distinct message keyed to its `loadStatus` value.

**Structured-extraction depth.** Deferred to plan `01-03`, where it is resolved in full. This
plan registers only `GenericMarkdownHandler`, so every artifact in the sparse-empty fixture
arrives as `kind: 'unknown'` with frontmatter lifted as an open map. That is the correct
tracer behavior: the dispatch mechanism is proven before any typed handler exists.

**No runtime schema-validation library.** Frontmatter and JSON are read as `Record<string, unknown>`
and known fields are lifted with defaults (RESEARCH Open Question 1). No `zod` or equivalent is
added in this phase.

**Layer A — `src/planning-fs/in-memory-fs.ts`.** Export

**Layer B types — `src/planning-repo/types.ts`.** Export the `LoadStatus` discriminated union with

Export `WarningStage` as the union of `read`, `frontmatter`, `structured-extraction`, `assembly`

**Layer B — `src/planning-repo/frontmatter.ts`.** Export `tryParseFrontmatter(content)` returning
`{ data, body, warning? }`. It calls `gray-matter` inside a try/catch — always, with no unguarded
call path anywhere in the codebase — and on failure returns the entire input as `body`, `{}` as
`data`, and a warning at stage `frontmatter` with salvage text stating the body survived and the
frontmatter did not. Export `tryParseJson(content)` with the same guarded shape at stage
`structured-extraction`. `tryParseJson` must strip `__proto__`, `constructor`, and `prototype` keys
at every depth of the parsed value before returning it, so that an open-map read of an untrusted
`config.json` cannot reach an object prototype. Neither function ever throws.

**Layer B — `src/planning-repo/warnings.ts`.** Export `class WarningCollector` with

`all()` returning them in insertion order. This is the single source D-09 requires: the flat
`snapshot.warnings` array and each artifact's own `warnings` array hold references produced by this

**Layer B — `src/planning-repo/discovery.ts`.** Export `discover(fs)` returning `ArtifactRef[]`.
In this task it walks `.planning/` recursively from the root, skips `research/.cache/`, records
each skipped path in a returned `exclusions` list so the omission is visible rather than silent,
and assigns every discovered file `kind: 'unknown'`. Dispatch is by filename and directory position

The full GSD naming grammar lands in plan `01-03`; the signature does not change.

**Layer B — `src/planning-repo/registry.ts`.** Export `HANDLERS`, an ordered array holding exactly

runs its `parse` inside a try/catch that converts any thrown error into a warning at the appropriate
stage rather than propagating. A read failure produces a stage `read` warning with salvage text
stating nothing was readable, and the artifact still appears in the snapshot with an empty body.
The generic handler is always last in the array; that ordering is load-bearing and must be stated in
a comment at the array declaration.

**Layer B — `src/planning-repo/handlers/generic.ts`.** Export `GenericMarkdownHandler` with
`kind: 'unknown'`, a `match` that returns `true` unconditionally, and a `parse` that lifts
frontmatter through `tryParseFrontmatter`, derives a title from the frontmatter `title` key or the
first level-one heading or the file path, and keeps the raw body verbatim.

**Layer B — `src/planning-repo/assemble.ts`.** Export
`assembleDomainModel(parsed, warnings, rootPath)` returning a `Project`. In this task it populates
only the root-document slice: `rootPath`, `name`, the parsed root artifacts keyed by path,
`config` as an open map (empty when `config.json` is absent), and empty `milestones`, `phases`,
`quickTasks`, `requirements` collections. Empty collections are the honest representation of a
project with nothing to parse — never `null`, never a thrown error.

**Layer B — `src/planning-repo/snapshot.ts`.** Export `class PlanningRepository` constructed from a
`PlanningFilesystem` and a canonicalized `rootPath`. `refresh()` runs the whole pass — target check,
discover, parse, assemble — and returns a NEW immutable `ProjectSnapshot`; it never mutates a
previously returned snapshot. `load()` calls `refresh()` once. Neither ever throws: a failed target
check short-circuits to a snapshot carrying the failing `LoadStatus` with `project: null` and an
empty warnings list. `getSnapshot()` returns the last snapshot and throws only when called before
`load()`, which is a programmer error and not a data condition. Set `readAt` to an ISO timestamp on
every refresh.

**Domain — `src/domain/model.ts`.** Export the entity types with zero imports from `planning-fs/` or
`planning-repo/`: `Project`, `Milestone`, `Phase`, `PhaseIdentity`, `Plan`, `PlanSummary`,
`Requirement`, `Artifact`, `QuickTask`. `PhaseIdentity` is the compound
`{ milestoneVersion: string | null, number: string, projectCode: string | null, slug: string }` —
phase number alone is never an identity. `Phase` carries `roadmapComplete` and `diskStatus` as two
separate fields that are never merged. Every status-like field is an open `string`, not a closed
union, so an unrecognized value from a future GSD version passes through instead of failing.
`Artifact` is the universal base shape (`id`, `path`, `kind`, `frontmatter`, `title`, `body`,
`bodyLength`, `bodyHash`, `mtimeMs`, `warnings`); typed artifacts in plan `01-03` extend it.

**Serializer — `src/planning-repo/serialize.ts`.** Export
`normalizeForGolden(snapshot, rootPath, options)` where `options` is `{ stable, withBodies }`. This
is the ONE function that owns every machine-varying value (D-07). It always rewrites absolute paths
that begin with `rootPath` into project-root-relative form. Under `stable`, it replaces `mtimeMs`
with `0` and `readAt` with a fixed placeholder string. When `withBodies` is false — the default —
it removes each artifact's `body` and keeps `bodyLength` and `bodyHash` (a hex SHA-256 of the raw
body computed via `node:crypto`); when true, it keeps the raw body as well. Mention positions, when
they arrive in plan `01-04`, must survive this function unchanged. Emit object keys in a stable
order so the JSON diff is deterministic.

**CLI — `src/cli/target-path.ts`.** Export
`resolveTargetPath(rawPath)` returning either `{ rootPath, planningDir }` or a non-`ok` `LoadStatus`.
It expands a leading `~` using the home directory (Node does not do this, and the argument arrives
through `npm run --` and through Vitest without a guaranteed shell pass), resolves to absolute, then
canonicalizes with `realpathSync` — following a symlink supplied as the root argument without
objection. It then accepts either shape: a directory containing a `.planning` child, or a directory
that is itself named `.planning` and contains `PROJECT.md` or `STATE.md`. Canonicalization happens
exactly once; every downstream caller receives only the canonicalized path and never re-derives it.

**CLI — `src/cli/snapshot.ts`.** Export
`buildSnapshotJson(rawPath, options)` — the single function both the CLI and the test suite call
(D-05) — which resolves the target, constructs a `LocalFsPlanningFilesystem`, runs
`PlanningRepository.load()`, and returns `normalizeForGolden(...)`. The module's executable half
parses `process.argv` by hand for one positional path plus the two boolean flags `--with-bodies` and
`--stable`; no argument-parsing library. It prints `JSON.stringify(result, null, 2)` to stdout and
exits 0 on success. On a non-`ok` load status it prints the status message to stderr and exits with
a nonzero code, while still printing the snapshot JSON to stdout so the failure is inspectable. The
three failure messages are: for a missing path, a line naming both the raw argument and the resolved
path; for a directory that exists but holds no `.planning`, a line naming the resolved path and
stating no planning directory was found inside it; for an unreadable target, a line naming the
resolved path and stating permission was denied.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| CLI argument → `resolveTargetPath` | An arbitrary, user-supplied filesystem path enters the process here and determines everything the tool reads. |
| Target `.planning/` tree → `LocalFsPlanningFilesystem` | File contents and directory structure are attacker-influenced in the sense that the tool is pointed at trees it did not author; the tool must not be steered by them. |
| Parsed YAML / JSON → domain model | Untrusted-*shape* document content crosses into object construction here. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-01-01 | Tampering / Information Disclosure | `src/planning-fs/local-fs.ts` — symlink inside the tree resolving outside the canonicalized root | high | mitigate | `resolveContained` canonicalizes every read/list target and refuses any result outside the root, throwing `PathEscapeError`; Task 2 adds the covering test and the visible stage `read` warning |
| T-01-03 | Tampering | `src/planning-repo/frontmatter.ts` — prototype pollution through open-map `JSON.parse` of `config.json`/`HANDOFF.json` (DATA-03 mandates open maps) | high | mitigate | `tryParseJson` strips `__proto__`, `constructor`, and `prototype` keys at every depth before returning; parsed maps are never spread onto a prototypal object |
| T-01-02 | Denial of Service | `gray-matter` and `JSON.parse` call sites | medium | mitigate | Every call is inside try/catch (`tryParseFrontmatter`/`tryParseJson`); `load()` and `refresh()` are proven total by Task 2's test set |
| T-01-06 | Denial of Service | `src/planning-repo/discovery.ts` — symlink cycle or pathological tree during the walk | medium | mitigate | Track canonicalized paths already visited during a walk and skip repeats; record each skip in `exclusions` so the omission is visible |
