<objective>
Make a damaged file legible instead of loud, and visible before it is opened.

TGT-06 requires that a single malformed file is isolated to its own view - never blanking another
page, never crashing the app. Phase 1 already proved that at the repository layer: a corrupted file
degrades to its body plus a recorded `ParseWarning` while the rest of the tree parses cleanly. What
Phase 4 owes is the user-visible half. Today `artifact-page.tsx` renders every warning as a
persistent notice row stacked above the document - exactly the treatment D-10 rejected - and
`search-page.tsx` marks a warned file with the same quiet tone it uses for ordinary absence, which
contradicts D-12's "mark degradation before the user opens it."

Purpose: a degraded file is still the file the reader came for. D-10 and D-11 move the diagnosis
out of the reading path and behind one badge; D-12 puts the mark where the reader chooses what to
open; D-13 keeps the recovered body ranked like any other, because demoting it would hide the
document to punish its metadata.
Output: one shared tone derivation, three consistently marked surfaces, and a badge that explains
itself on demand.
</objective>
