## Assumptions this plan makes that the verification report does not state

The gap report names the defect and the acceptance floor; it does not author the replacement copy or
say how far the branch should reach. These are the planner's calls, recorded here rather than buried
in an `<action>`:

1. **Three branches, not two.** The report's `missing` item allows branching on tone *or* on
   structural-versus-rendering-only. This plan does both, because the report itself names both
   defects (the unreadable contradiction *and* the false metadata claim on a rendering-only warning)
   and a tone-only branch leaves the second one live.

2. **A new module, not an inline ternary.** `04-REVIEW.md`'s suggested fix is an inline ternary in
   the JSX. This plan puts the strings and the selection in
   `src/presentation/artifact-warning-summary.ts` instead, for one reason that is not style: the
   contract test can then import the constants and assert the page contains *none* of them, which is
   a stronger and more durable check than grepping the page for a sentence the test would have to
   restate. It also mirrors the shape 04-03 already established for `artifact-warning-tone.ts` —
   presentation vocabulary lives in `src/presentation/`, the page renders it.

3. **The exact replacement wording is the planner's**, and is fixed in Task 1's `<behavior>` so the
   executor has no latitude to improvise prose. It deliberately explains the empty document body
   rather than merely avoiding the false claim, so the disclosure and the "no authored body" notice
   read as one account. Whether it *reads* coherently to a person is not assertable by test — that
   is the backstop truth and the `<human-check>` in Task 3.

4. **Structural damage outranks a rendering warning when both are present.** An artifact with both
   kinds gets the metadata sentence; the rendering warning is still listed verbatim in the
   technical-details section below, so nothing is hidden. The alternative — a fourth combined
   string — buys a sentence nobody will read for a case the technical details already cover.

5. **An inconsistent input yields silence, not a guess.** If a caller ever passes a non-null tone
   with zero warnings of either kind (unreachable through `artifactWarningTone`, which returns
   `null` for an empty warning list), the function returns `null` and the page renders no summary
   paragraph. Honest silence beats a fabricated claim; the technical-details section still renders.

6. **`04-UI-SPEC.md`'s Copywriting Contract is updated, not left stale — an explicit, argued
   widening of the file set beyond the two source files the gap names.** Line 179 of that file
   currently pins the single sentence as *the* D-11 copy. Shipping the fix without touching it
   leaves the phase's own design contract asserting something the code no longer does, which the
   next verification or UI review would correctly flag as a fresh contradiction. The edit is one
   table row becoming three, in the same file, for the same element. No other row, section, or
   consideration in that document changes, and no PLAN.md or SUMMARY.md is touched.

7. **Not done, and why.** The empty-document notice ("This artifact has structured metadata but no
   authored body", `artifact-page.tsx` ~line 285) is left exactly as it is. Making it tone-aware
   would mean threading the tone into `DocumentView`, which is prop-plumbing across a component
   boundary the gap does not name, for a message the new summary now explains from above. If the
   human check in Task 3 finds the pair still reads badly, that plumbing is the follow-up — it is
   named here so a later reader sees it was considered, not missed.
