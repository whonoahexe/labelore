# Phase 4 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**Read this contract as hardening, not redesign.** Phases 2–3 shipped the complete visual
language (hand-authored CSS over Tailwind v4 oklch tokens, `@base-ui/react` headless primitives,
no shadcn CLI-generated components). Phase 4 adds no new page and touches five small, precisely
scoped surfaces — the global Refresh control and its failure toast, a damaged-artifact warning
badge/disclosure on the artifact page, a warning indicator shared by the tree and search results,
a single generic empty-state pattern reused across every "optional content is absent" case, and a
dedicated whole-app invalid-project failure screen. Every one of them is specified below in terms
of classes, tokens, and components that already exist, plus the two genuinely new primitives
(`@base-ui/react/toast`, a copy-to-clipboard affordance) named explicitly.

**Existing precedent this phase corrects, not just extends.** Two gaps were found reading the
shipped Phase 2/3 code against Phase 4's decisions (D-10 through D-13) and are called out inline
below rather than silently left as-is:

1. `src/web/pages/search-page.tsx`'s `row.unreadable` chip already renders `data-tone="quiet"` —
   the same tone used for ordinary absence — which visually contradicts D-12's "mark degradation…
   before the user opens it." This phase retones it (see **Color**).
2. `artifact-page.tsx` currently renders every parse warning as a persistent `<p className="notice
   warning">` row before the document body — exactly the "persistent banner" option D-10
   explicitly rejected in favor of the on-demand badge. This phase replaces that treatment.

## Spacing Scale

The codebase runs a fluid rem-based system, not a rigid 4px grid — fixed rem paddings for chrome,
`clamp()` for content gutters. Values below are the actual production values (16px root),
carried over unchanged from Phase 2/3's UI-SPECs; Phase 4 adds no new spacing token.

| Token | Value | Usage (existing citation) |
|-------|-------|----------------------------|
| xs | 4px (`0.25rem`–`0.4rem`) | Icon-to-text gaps inside chips/labels — `.status-chip { gap: 0.4rem }` |
| sm | 8px (`0.5rem`) | Compact list-item gaps — `.attention-list`, `.criteria-list` |
| chip-pad | ~9–10px (`0.55rem`–`0.65rem`) | Chip/badge internal padding — `.status-chip { padding: 0.38rem 0.55rem }`. Reuse verbatim for the new warning badge; do not round to 8/16. |
| md | 16px (`1rem`) | Default element spacing, panel body padding |
| lg | 24px (`1.5rem`) | Section-internal gaps |
| xl | 32px (`2rem`) | Major inter-section gaps |
| section-pad | `clamp(1.25rem, 3vw, 2rem)` | Card/panel padding that scales with viewport — reuse for the invalid-project screen's central panel |
| page-pad | `clamp(2rem, 5vw, 5.5rem) clamp(1rem, 4vw, 3.5rem) 7rem` | `.page-stack` outer padding |

**New for Phase 4 — the invalid-project screen has no `.page-stack`/shell chrome around it** (D-14:
navigation, search, and tree are hidden because there is no valid project). Center its panel in
the viewport using the same `section-pad` value for its own internal padding, but give the screen
itself a simple `min-height: 100vh; display: grid; place-items: center` — it is the one surface in
the app that does not sit inside `.shell-content`.

**New for Phase 4 — toast placement.** No existing precedent for a fixed-position overlay exists
in the codebase. Anchor `Toast.Viewport` to the bottom-right of the viewport with `1.5rem` (`xl`)
inset from both edges — the only viewport-fixed overlay convention this app needs, sized to clear
the sticky `z-index: 20` header without competing with it.

Exceptions: none beyond the two new placements above.

## Typography

Roles carried over unchanged from Phase 2/3; Phase 4 introduces no new size or weight.

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body | 13px (`0.82rem`) | 400 (`--font-sans`) | 1.55 |
| Label / eyebrow | 11px (`0.67rem`), uppercase, `letter-spacing: 0.08em` | 600 (`--font-heading`) | 1.3 |
| Heading (section h2/h3) | 21px (`1.3rem`) | 600 (`--font-heading`) | ~1.2 |
| Display | `clamp(2.6rem, 7vw, 5.6rem)` | 600 | 0.9 |

Applied to Phase 4's five surfaces:

- **Refresh control label / "Refreshing…" status text**: Label/eyebrow — 11px/600/uppercase,
  identical treatment to the existing `.snapshot-status small`/`time` pair it sits beside. The
  status text swaps in place (`Snapshot read {time}` → `Refreshing…`); no layout shift, since both
  strings render in the same `.snapshot-status` slot at the same size.
- **Toast title/body**: Body — 13px/400/1.55 for the message, Label/eyebrow for an optional
  "Refresh failed" title, matching `.notice h2`/`.notice p`'s existing size split at toast scale.
- **Warning badge label**: reuse `.status-chip` verbatim — 0.64rem/600/uppercase. Never a new chip
  size.
- **Warning disclosure body** (plain-language summary + technical detail): Body — 13px/400/1.55 for
  the plain-language summary; the technical detail (path, stage, message) renders in the same
  monospace `--font-heading` treatment `.artifact-path`/`.source-note` already use for file paths,
  at 0.7–0.75rem, so raw diagnostic text is visually distinct from prose without inventing a code
  font.
- **Invalid-project screen heading**: Heading role (21px/600) is too quiet for the app's one
  full-screen failure state — use the Display scale's lower end, `clamp(1.8rem, 4vw, 2.6rem)`,
  large enough to read as "the whole app failed" without reaching for the dashboard hero's own
  `clamp(2.6rem, 7vw, 5.6rem)`, which is reserved for the current-position headline.
- **Checked-path field**: monospace, `--font-heading`, 0.85rem, matching `.artifact-path`'s
  existing code-style treatment (see **Color** for its container styling).
- **Copyable restart command**: identical monospace treatment to the checked-path field, at the
  same 0.85rem — both are "copy this exact string" affordances and should look like the same
  component, differing only in an icon/label above each (`Path checked` / `Restart command`).

## Color

The existing 60/30/10 split carries over unchanged. Phase 4 makes exactly one semantic addition —
reusing `--destructive` for data-warning flags — extending Phase 3's own precedent rather than
introducing a third semantic color.

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `--background` / `--card` — `oklch(1 0 0)` light, `oklch(0.145 0 0)` dark | Page canvas, invalid-project screen background, toast surface (`--card`) |
| Secondary (30%) | `--muted` / `--sidebar` — `oklch(0.97 0 0)` / `oklch(0.985 0 0)` light, `oklch(0.269 0 0)` / `oklch(0.205 0 0)` dark | Empty-state icon backdrop (quiet, matches `.empty-flow`'s existing dashed-border-on-`--background` treatment — no fill change needed, D-09 asks for quiet not decorated); `--sidebar` continues backing the tree, where the warning indicator now also lives |
| Accent (10%) | `--primary` — `oklch(0.553 0.195 38.402)` light, `oklch(0.47 0.157 37.304)` dark | Reserved for exactly: (1) the Refresh icon's resting/hover color, matching `.snapshot-status > svg { color: var(--primary) }` right beside it; (2) the refresh spin animation's stroke color while `Refreshing…` is active; (3) any focus ring (`--ring`, distinct token, listed here only to exclude it from accent). Never used for the warning badge, the empty-state icon, or the invalid-project screen — none of those are actions. |
| Destructive | `--destructive` — `oklch(0.577 0.245 27.325)` light, `oklch(0.704 0.191 22.216)` dark | **Extended this phase** to both damaged-artifact states: (1) the D-10 warning badge (structured parsing failed, body survived) uses a new `.status-chip[data-tone='warning']` rule — same visual formula as the existing `[data-tone='destructive']` rule (`border-color: color-mix(in oklch, var(--destructive) 55%, var(--border)); background: color-mix(in oklch, var(--destructive) 8%, transparent); color: var(--destructive)`) reused verbatim under a semantically distinct selector, so a future genuinely-destructive action never gets silently retoned by a CSS rename; (2) the tree/search "nothing salvageable" indicator reuses `[data-tone='destructive']` directly, since it is the same "flag a data problem, not a destructive action" pattern Phase 3 already established for the traceability mismatch flag. Also reserved for: the toast's error accent (left border or icon color, matching `.notice.destructive`'s `border-left: 3px solid var(--destructive)`) and the invalid-project screen's icon/heading accent (the one place in the app where "the whole app failed" legitimately reads as more severe than an inline notice). |

Accent reserved for: the Refresh control (icon, hover, active-refresh state) and existing uses only
(text-links, focus rings, current-route tree highlight). Destructive reserved for: the two
damaged-artifact tones above, the failure toast, and the invalid-project screen. Never used for:
the generic empty-state icon (D-09 requires it read as neutral, not attention-worthy — use
`--muted-foreground`, matching `.quiet-state svg`/`.empty-flow svg`'s existing color, **not**
`--primary`, despite `.empty-flow svg` currently being colored `--primary` in Phase 2's CSS — see
note below).

**Correction carried into this phase's copy, not just new code:** `.empty-flow svg` is currently
styled `color: var(--primary)` in `globals.css` (see Spacing Scale citation), which reads as an
accent/action color on a state that D-09 explicitly requires read as neutral. Phase 4's "Nothing
here yet." reuse should override this to `--muted-foreground` wherever it renders the new generic
empty state (D-08) — existing uses of `.empty-flow` for genuinely different content (e.g. "no
archived milestones") are unaffected unless already using the shared class Phase 4 changes.
