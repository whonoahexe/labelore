<objective>
Prove the refresh seam end to end and make the dashboard state the age of what it shows.

This is the phase tracer: one path wired through every layer Phase 4 touches - the existing
`PlanningRepository.refresh()` seam, a new server route, the server's derived-view bundle, the
TanStack Query cache, and the global header. It delivers TGT-08 whole (every view states when its
data was read; a Refresh action re-reads the project through the same seam a future file watcher
will call) and implements D-01, D-02, D-03, D-04 and D-05.

Purpose: a refresh that replaces some derived data and not the rest is worse than no refresh at
all, because the timestamp would then describe data that is only partly that old. Proving the
atomic replacement first is what lets the three expansion plans build on a header that never lies.
Output: `POST /api/refresh`, a header Refresh control, the codebase's first toast primitive, and
two automated suites that pin the contract.
</objective>

Server, `src/server/index.ts`:

Widen `SnapshotSource` to `{ getSnapshot(): ProjectSnapshot; refresh?(): Promise<ProjectSnapshot> }`.
Keep `refresh` optional - `test/server/deep-links.test.ts` and `test/server/search-index.test.ts`
both construct bare object-literal sources and must keep compiling unchanged. `PlanningRepository`
already satisfies both members structurally, so `createSnapshotSource` keeps returning the
repository itself on the success path.

Introduce a `DerivedViews` interface holding `presentation`, `artifactIndex`, `referenceRegistry`
and `searchIndexState`, and a `buildDerivedViews(snapshot)` function that constructs all four from
one snapshot. Hold it in a single mutable `let derived = buildDerivedViews(source.getSnapshot())`
inside `createApp`. Per D-05 every read handler now serves from `derived` rather than recomputing
`toProjectPresentation(source.getSnapshot())` per request: `/api/presentation`, `/api/dashboard`,
`/api/roadmap`, `/api/history`, `/api/tree`, `/api/traceability`, `/api/search`, `/api/artifacts/*`
and `/api/documents` all read `derived.presentation` / `derived.artifactIndex` /
`derived.referenceRegistry` / `derived.searchIndexState`. Replacing `derived` with a
freshly built bundle in one assignment is the atomic swap D-05 requires - never mutate the
existing bundle field by field.

Add `app.post('/api/refresh', ...)`:
  - Same-origin gate (threat T-04-01-01/02): read the `sec-fetch-site` request header; when it is
    present and its value is not `same-origin`, return `c.json({ refreshed: false, reason:
    'cross-site' }, 403)` without touching the filesystem. An absent header (curl, the smoke probe)
    passes.
  - Coalescing: hold a `let inFlight: Promise<ProjectSnapshot> | null` in `createApp` scope. When a
    refresh is already running, await the same promise instead of starting a second filesystem walk,
    and clear `inFlight` in a `finally`. This is the TGT-06 concurrency edge and D-05's guarantee
    that two callers cannot observe two different rebuilds.
  - No-refresh source: when `source.refresh` is undefined, return HTTP 200 with
    `{ refreshed: false, readAt, loadStatus }` taken from `derived.presentation`. A source with
    nothing to refresh into is not an error (TGT-08 empty edge).
  - Success: await the refresh, assign `derived = buildDerivedViews(snapshot)` in one statement,
    then return HTTP 200 `{ refreshed: true, readAt: snapshot.readAt, loadStatus: snapshot.loadStatus }`.
    A failed target check comes back as a non-ok `loadStatus` inside a real snapshot, not an
    exception - preserve that: it is still a 200.
  - Unexpected rejection: `PlanningRepository.refresh()` documents that it never throws, so wrap the
    await in try/catch purely as a boundary. On rejection leave `derived` untouched (D-04 retains
    the previous snapshot) and return `c.json({ refreshed: false, error: 'Refresh failed' }, 500)`.
    Never let a rejection escape the handler.

## STRIDE Threat Register

|-----------|----------|-----------|----------|-------------|-----------------|
| T-04-01-01 | Denial of Service | `POST /api/refresh` in `src/server/index.ts` | medium | mitigate | Coalesce concurrent refreshes into one in-flight promise so N simultaneous requests cause at most one filesystem walk (Task 1), and reject any request whose `sec-fetch-site` header is present and not `same-origin` with a 403 before touching disk - this blocks a cross-site form POST from a page the user happens to have open while the tool runs. |
| T-04-01-02 | Tampering | `POST /api/refresh` request surface | medium | mitigate | The endpoint accepts no body, no query parameter and no header other than the same-origin gate above, so there is no attacker-controlled input on the refresh path; the refresh target is fixed at process start from argv. |
