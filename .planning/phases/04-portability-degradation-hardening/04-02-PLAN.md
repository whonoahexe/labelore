<objective>
Give an invalid startup target its own honest screen.

TGT-07 requires that pointing GSD Lore at a nonexistent path, an unreadable path, or a directory
with no `.planning/` produces a clear message naming the problem and the path that was checked. The
backend already produces exactly that message - `LOAD_STATUS_MESSAGES` in `src/cli/target-path.ts`
has carried the four wordings since Phase 1. What is missing is the surface: today a failed load
falls through to a dashboard-shaped page inside a shell whose navigation, search and tree all point
at a project that does not exist.

Purpose: D-14 makes the failure screen replace the routed tree rather than sit inside it, because
there is nothing to navigate; D-15 keeps one treatment for all four statuses so the user reads the
detail line rather than decoding a visual language; D-16 and D-17 make the two strings the user
actually needs - the path that was checked and the command to try again - copyable.
Output: `InvalidProjectScreen`, a router-level gate above `AppShell`, and automated proof.
</objective>
