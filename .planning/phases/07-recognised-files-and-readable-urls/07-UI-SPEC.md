# Phase 7 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**Scope.** Phase 7 is mostly plumbing (recognition, URL grammar, redirects). Every existing page keeps
its design; only the URLs they link to change. The user-visible surface this phase adds or changes is
small and is the whole of this contract:

1. The **image page** (D-08).
2. The **binary and large-file info card** (D-09, plus the oversized-text policy).
3. **Drawer file rows** for binaries and for newly recognised unprefixed files.
4. The **not-found page**, which now names the path it looked for (D-13).
5. The **silent legacy redirect** (D-12): what the user sees, which is nothing.

Everything is built from the vocabulary already in `docs/design-language.md`. This contract adds no
class name, no token and no type size. It adds two things to existing code, both listed under
"Surfaces and Interaction Contract": an optional `defaultFit` prop on `FigureFrame` and two
element-scoped CSS rules for an `img` inside `.figure-frame-body`.

Not designed here: designed pages for the newly recognised types (Phases 9-11), the settings page and
the Source mode redesign (Phase 12), search facets and the palette (Phase 13), the project switcher
(Phase 8). Images and binaries have no View/Source toggle in this phase; Phase 12 (SRC-02) gives
Source mode its plain notice for them.

## Spacing Scale

Declared scale, the contract for everything Phase 7 writes: 4, 8, 16, 24, 32 (px), every value a multiple of 4 and inside the standard set (4, 8, 16, 24, 32, 48, 64). 48 and 64 are not used by any Phase 7 surface. Values are reached only through the existing `--space-*` tokens; no literal `px` or `rem` in new CSS.

| Token | Value | Usage |
|-------|-------|-------|
| `--space-1` | 4px | Gap between a metadata key and its value |
| `--space-2` | 8px | Compact element spacing, record row gap |
| `--space-4` | 16px | Leading column of a drawer file row, `metadata-record` inset |
| `--space-6` | 24px | Page rhythm (`artifact-page` gap), notice padding |
| `--space-8` | 32px | Notice top margin (existing `.notice`) |

Phase 7 adds no new spacing declaration: its two new CSS rules (see Surfaces, section 1) set no spacing at all, and every page it builds is composed from existing classes. Any markup the executor adds beyond that must pick from the five tokens above.

Legacy inherited values (context, not contract values). Existing rules that the reused components already apply, unchanged, contain steps outside the standard set: 6px (`--space-1-5`, `.status-chip` padding, breadcrumb gap), 10px (`--space-2-5`, `.metadata-record` row gap and `.notice h2` margin), 12px (`--space-3`, `.artifact-heading` gap, `.metadata-panel h2` margin, drawer padding), 20px (`--space-5`, figure frame body padding) and 40px (`--space-10`, drawer row minimum height). This phase must not edit them (it reuses the existing token scale and pages unchanged). They do render on the new pages by inheritance: the image page's 20px figure-frame body padding, and the info card's 10px `metadata-record` gap and 12px `metadata-panel h2` margin. The executor must not copy them into new rules. Rebasing those rules onto the standard set is a separate cleanup, not Phase 7 work.

Touch targets: drawer rows stay at their existing 40px minimum and the `FigureFrame` chips keep their existing size; the 44px minimum is not applied because these are existing, desktop-first controls and the phase does not rebuild them.

## Copywriting Contract

Plain, sentence-case, no exclamation marks. Strings in braces are filled at runtime and rendered as text by React (never as HTML).

| Element | Copy |
|---------|------|
| Primary CTA | None. This phase adds no action. The one link on its new pages is the existing `Return to the dashboard` on the not-found page. |
| Image page eyebrow | `Image` |
| Image page title | `{file name}` as stored, with extension and original case |
| Image page facts (header `meta` row, `source-note`) | `{Type} · {size}`, then ` · {width} × {height} px` once the browser reports it, or ` · Dimensions unknown` when it reports 0 or the image fails |
| Image frame title (`figure-frame-title`) | `Preview` |
| Binary page eyebrow | `Binary file` |
| Binary page lead (`artifact-lead`) | `Labelore does not show this file's contents.` |
| Large-text page eyebrow | `Large file` |
| Large-text page lead | `Labelore does not read text files larger than 1 MB.` |
| Info card heading | `File details` |
| Info card keys | `Name`, `Type`, `Size`, `Folder` (this order) |
| Empty state heading | Not applicable. These pages are never empty: a file always has a name, type and size. The drawer keeps `Nothing here yet.` where it already shows it. |
| Empty state body | Not applicable. Internal files leave no placeholder, count or "hidden" row anywhere (D-11). |
| Error state: image cannot be shown | Heading `This image could not be shown`; body `The file is listed in the project, but your browser could not display it.` Rendered as `notice render-issue` in place of the frame. The header and facts row stay. |
| Error state: image over the byte cap | Eyebrow `Image`; lead `This image is larger than {cap} MB, so Labelore does not load it.`; info card as for a binary. Cap value is open (see UI Considerations). |
| Not-found (any miss, including an internal file, an old link that resolves nowhere, and a bare folder URL) | Eyebrow `Not found`; h1 `This local route does not exist.`; notice heading `Nothing is mapped here`; body `Labelore looked for this address and found no file or page there.`; then the address as typed; then link `Return to the dashboard`. |
| Not-found, address starts with a different project name | Same page; body becomes `This address starts with a different project name than the one that is open ({slug}).`; the link still reads `Return to the dashboard` and goes to `/{slug}`. |
| Destructive confirmation | None. Labelore is read-only and this phase adds no destructive action. |

Type labels (the `Type` value and the facts row), keyed by lowercase extension. Anything not listed reads `Binary file`, with the extension appended when there is one (`Binary file (.dat)`).

| Extension | Type label |
|-----------|-----------|
| png, jpg, jpeg, gif, webp, avif, bmp | `PNG image`, `JPEG image`, `GIF image`, `WebP image`, `AVIF image`, `BMP image` |
| svg | `SVG image` |
| ico | `Icon image` |
| pdf | `PDF document` |
| zip, gz, tar | `ZIP archive`, `GZip archive`, `Tar archive` |
| woff, woff2, ttf, otf, eot | `Font (WOFF)`, `Font (WOFF2)`, `Font (TTF)`, `Font (OTF)`, `Font (EOT)` |
| mp3, mp4, mov, webm | `MP3 audio`, `MP4 video`, `QuickTime video`, `WebM video` |
| wasm | `WebAssembly module` |
| sqlite, db | `Database file` |
| exe | `Executable` |
| text file over the size limit | `Text file` (the extension is not repeated) |

Size format, one shared function used by the drawer badge, the image facts row and the info card: under 1024 bytes `{n} B`; under 1 MB `{x.x} KB`; then `{x.x} MB`, `{x.x} GB`. One decimal, with a trailing `.0` dropped (`48.2 KB`, `2 MB`). The base is 1024 and the unit is written KB / MB. The exact count sits in the value's `title` (`48,213 bytes`).

Folder value: the project-relative folder that holds the file, POSIX separators, starting `.planning/` (`.planning/ui-reviews/screenshots`). It is the same relative path the copy-path button copies, minus the file name.

## Surfaces and Interaction Contract

### 1. Image page (D-08)

Layout, top to bottom, inside `<main className="artifact-page page-stack">`:

1. `ArtifactHeader`, plain variant, unmodified: `crumbs` as the document page builds them (Dashboard, Roadmap, milestone and phase crumbs when the file belongs to one, then the file name as the last, non-link crumb), `eyebrow="Image"`, `title={file name}`, `path={artifact.path}` (so the copy-path icon button appears), and `meta` holding the facts row in `source-note`.
2. `FigureFrame` with `title="Preview"` and no caption. Its bar gives Fit to width / Actual size, Grid and Expand with no new code.
3. Inside the frame: a single `<img>` with `alt={file name}`, `src` set to the image-bytes route for this artifact's route (never a path), and `onLoad` / `onError` handlers. **Never** `<object>`, `<iframe>`, `<embed>`, an inline `<svg>` or `dangerouslySetInnerHTML`. An SVG is shown exactly like a PNG.

Focal point: the image inside the frame. The frame sits directly under the header, is the only bordered block on the page and is full column width, so the eye goes file name (display h1), then the picture; nothing else competes with it (no outline column, no side panel, no caption).

Copy-path button: the existing icon-only `CopyPathButton`, accessible name `Copy file path` (`aria-label`), tooltip `title` = the project-relative path, and a polite `role="status"` `sr-only` announcement `Path copied` for about 1.5s after a successful copy. It is the only control in the header besides the breadcrumbs. No new label is introduced.

Changes to existing code (the only two):
- `FigureFrame` gains an optional `defaultFit?: boolean` prop (default `false`) that seeds the `fit` state. The image page passes `true` because screenshots are usually wider than the column. Every other caller is unchanged.
- `globals.css` gains two element-scoped rules, token-free and class-free:
  `.figure-frame-body img { display: block; max-width: none; height: auto; }` and
  `.figure-frame-body img[data-fit='true'] { max-width: 100%; }`. The `<img>` sets `data-fit` from the render-prop's `fit` flag. The Expand dialog calls the render prop with `false`, so it shows actual size. Fit never upscales a small image. Run the CSS source-order and token-guard tests after adding them.

Interaction:
- Opens in Fit to width. The first chip reads `Fit to width` and, when pressed, `Actual size` (existing `FigureFrame` behaviour). In Actual size a wide image scrolls horizontally **inside the frame body**, never the page.
- Grid draws the existing grid-paper backdrop behind a transparent image. Expand opens the dialog at actual size; Escape or Close dismisses it and focus returns to the Expand chip (Base UI behaviour).
- The image is not a link. There is no "open image", no "download", no "open in new tab" and no link to the bytes URL anywhere on the page (D-08 and D-09 forbid a raw-serve affordance).
- Dimensions come from `naturalWidth` and `naturalHeight` on `onLoad`. Before load the facts row reads `{Type} · {size}`; after load ` · {w} × {h} px` is appended; if either is 0 it reads ` · Dimensions unknown`. On `onError` the frame is replaced by the error notice and the facts row ends in `Dimensions unknown`.
- Animated GIF, WebP and APNG play natively; there is no pause control.
- No View/Source toggle. No `document-outline`. No outline column. The page is one column.

### 2. Info card for binaries and large text (D-09, D-10)

Inside `<main className="artifact-page page-stack">`:

1. `ArtifactHeader`, plain variant: `eyebrow="Binary file"` (or `Large file`), `title={file name}`, `lead` as in Copywriting, `path={artifact.path}`.
2. `<div className="metadata-panels">` holding one `metadata-panel metadata-panel-known` (via `MetadataPanel`, or the same markup directly) with `h2` `File details` and one `metadata-record` of four rows, each a `dt` key and a `dd` holding a `metadata-scalar`: `Name`, `Type`, `Size`, `Folder`. The Folder value uses `artifact-path` so it wraps anywhere. The Size value carries the exact byte count in `title`.

Focal point: the `File details` card. The display-size file name and the one-line lead orient the reader, and the card is the only bordered block on the page, so it holds the answer to "what is this file" (Type and Size are the rows that matter). The copy-path button carries the same accessible name, `Copy file path`, and `Path copied` announcement as the image page.

Rules:
- No icon, no preview, no hex dump, no "contents hidden" placeholder box. The lead sentence and the card are the whole page.
- No link or button other than the copy-path icon button and the breadcrumbs. No download. No raw view.
- The page is static: no loading state (all values arrive in the presentation payload) and no error state of its own.
- A text file over the size limit is `fileClass: large`. It uses this same card with the `Large file` eyebrow and its own lead. It is not indexed and not readable in Source mode (Phase 12 owns that notice).

### 3. Drawer file rows (DATA-07, DATA-08, D-11)

Rows stay `Link.places-file-row` with the existing anatomy: leading spacer column, `places-label`, then trailing columns. Nothing in the drawer's two-column structure, phone drill-down or active-row rule changes.

- **Where.** Recognised unprefixed files (`COVERAGE.md`, `deferred-items.md`, `SKELETON.md`, `.continue-here.md`) and binaries that live in a phase folder appear in that phase's **After** stage, after the known post-plan documents in their existing order, then the recognised unprefixed files, then binaries, each group alphabetical by file name. The `After` stage heading already appears only when it has rows; keep that rule. Labels for recognised unprefixed files are the existing sentence-case label of their kind (`Coverage`, `Deferred items`, `Skeleton`, `Continue here`). A binary's label is its full file name with extension.
- **Mark.** A binary, an image or a large text file gets one trailing `places-badge` reading `{EXT} · {size}` (`PNG · 48.2 KB`, `PDF · 1.2 MB`, `JSON · 2.4 MB`). `{EXT}` is the lowercase extension upper-cased, at most 5 characters, else `FILE`. The badge never truncates; the label ellipsises first. For assistive tech the badge is `<span aria-hidden="true">PNG · 48.2 KB</span><span className="sr-only">, PNG image, 48.2 KB</span>`, the same sr-only pattern the warning indicator uses.
- **No grouping, no icon, no separate section.** Binaries sit inline in their folder, as quiet as any file. There is no per-type colour and no type icon. The leading column stays the empty `places-row-spacer`.
- **Active state.** While an image or binary page is open its row is `data-active='true'` and `aria-current='page'` through the existing mechanism (row URL equals the project-relative pathname).
- **Test hook.** A row for a non-text file carries `data-file-class="image" | "binary" | "large"` (an attribute, not a class).
- **Quick tasks** keep one row per task opening its plan; their files are not listed in the drawer in this phase. They stay reachable by URL, by the links documents make to them, and (for text) by search.
- **Absent on purpose.** Internal files (`state.json`, locks, `tmp/`, `async-jobs/`, `logs/`) are not in the artifact index, so no drawer row, no count, no "hidden files" toggle and no placeholder exists for them (D-11, and the toggle is a deferred idea).

### 4. Not-found page (D-11, D-13)

Keeps the existing structure (`main.page-stack`, `.eyebrow`, `h1`, `section.notice`, a link). The only changes are copy and one new line:

- Under the notice's first paragraph, a `<p className="artifact-path">` shows the address the user asked for: the **pathname as it appears in the address bar, decoded once**, including the project slug and without query or hash. It wraps anywhere (`overflow-wrap: anywhere` is in the rule). React escapes it; it is never a link and never HTML.
- One page serves every miss and says nothing about why: an unknown URL, an old link that resolves to no file (D-13), a `file/` URL naming an internal file (D-11), a bare folder URL such as `/labelore/notes` (no page in this phase), and a wrong project name. The page must not reveal that a path is internal or that a file exists but is hidden.
- There is no fallback to a parent page and no "did you mean". The link `Return to the dashboard` goes to the open project's dashboard, `/{slug}`.
- Focus: after a navigation to this page the `h1` is not focused programmatically (no existing pattern); the page scrolls to top like any route change.

### 5. Silent legacy redirect (NAV-11, D-12, D-14)

No visible UI. The contract is about what the user does **not** see:
- An old `m~`, `p~` or `a~` URL, `?doc=summary`, a bare milestone URL, or a live-milestone `/roadmap` alias replaces the history entry (`Navigate replace`) with the readable URL. The back button skips the old URL. There is no notice, banner, toast or "this link has moved" text.
- While the presentation payload is still loading, the redirect renders nothing and the shell shows its existing `Reading snapshot…` state. The not-found page must never flash before the redirect resolves.
- If the presentation request fails, the shell's existing notice shows and no redirect is attempted.
- If the old link resolves to no file, the redirect component renders the not-found page above, naming the **old** pathname.
- The redirect target is always built from resolved data as a same-origin path starting with a single `/`, never from request text.

### 6. Links and breadcrumbs across existing pages (NAV-09, NAV-10)

No visual change to any existing page. These are the user-visible rules that go with the URL change:
- Every internal link, breadcrumb, drawer row and DTO URL is project-relative and gains the project slug in one place (`web/nav.tsx`). The address bar always starts with the project name.
- A phase's breadcrumb "up" link to its milestone goes to `/{slug}/{version}/overview` (the phase list and progress page, D-04), which keeps today's behaviour with no redirect hop. Links that name a milestone as a destination (drawer milestone header, dashboard milestone entries) go to the milestone's roadmap: `/{slug}/{version}/roadmap`, or `/{slug}/roadmap` for the live milestone (D-02, D-03).
- `config.json` keeps opening in the existing generic document page with secrets masked (Phase 6); this phase adds no settings chrome.
- An in-document link to an image or other binary opens that file's page like any other artifact link, in the same tab.
