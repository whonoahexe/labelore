## Spacing Scale

Declared values (all multiples of 4), applied through existing tokens:

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px (`--space-1`) | Icon and square to text gap, chip gap, ruler cell gap |
| sm | 8px (`--space-2`) | Gap between a row's chips, gap between a label and its value |
| md | 16px (`--space-4`) | Row padding, tile padding, group gap inside a ledger |
| lg | 24px (`--space-6`) | Core-value card padding (horizontal), gap between ledger groups, section gap |
| xl | 32px (`--space-8`) | Spine indent, gap between the main column and the sticky margin, page top rhythm (through `page-stack` / `--space-fluid-*`) |
| 2xl | 48px | Not used by this phase |
| 3xl | 64px | Masthead vertical padding only, through `--space-fluid-10` |

Exceptions:
- Sketch-locked sub-grid values on the project page, kept because the sketch was approved with them: the spine rail and node geometry (`0.15rem`/`0.45rem` offsets that centre a `.sq` on a 1px rail), the square sizes (`0.6rem` node squares, `0.85rem` jump-strip squares). They are decoration geometry, not layout spacing. The planner writes them as `calc()` over `--space-*` tokens where an exact token exists and otherwise as one named custom property per page (`--view-project-node-offset`) so no bare `px`/`rem` appears in a rule.
- The gap between jump-strip squares is 4px (`--space-1`), rounded up from the sketch's 3px so every gap is a scale value; the difference is invisible at 0.85rem squares.
- The jump-strip squares have a hit area of at least 24px square under `@media (pointer: coarse)` (padding around the visible square); fine pointers keep the visible 0.85rem square.
- Tab links (`xs` button) are 28px high; on coarse pointers the ledger tab strip rises to 40px (`Button` size `sm`).

## Color

Tokens only. No literal colour anywhere; every rule checked in `:root` and `.dark`.

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `--background` (light `oklch(1 0 0)`, dark `oklch(0.125 0 0)`) | Page surface, spine, ledger rows |
| Secondary (30%) | `--card` / `--card-veil` / `--muted` / `--secondary`, hover `--state-hover`, hairlines `--border` and `--border-faint` | Masthead band (`--card-veil`), count tiles, group heads, the core-value card interior (`--background` on a `--border` frame), code chips (`--code-veil`) |
| Accent (10%) | `--primary` (light `oklch(0.553 0.195 38.402)`, dark `oklch(0.47 0.157 37.304)`) | Reserved list below |
| Destructive | `--destructive` | **Not used by this phase.** Open windows, critical findings, failed gaps and reversed decisions are document content, so they use the `missing` / `in-flight` / `quiet` families, never `destructive` or `warning` (user rule; design language). |

### Tone mapping (document content only; the parse-degradation tones never appear on any page here)

| Meaning | Tone | Mark |
|---------|------|------|
| Finished, holding, integrated, passed, shipped, zero open | `complete` | square filled `--primary` |
| Waiting on someone, partial, tech debt, needs a person | `in-flight` | square filled `--in-flight-fill` |
| Expected and absent, failed, blocker | `missing` | square outlined 2px `--missing-fill` |
| Neutral, not applicable, opted out, deferred, skipped, unknown | `quiet` | square dashed `--muted-foreground` |

The four-square vocabulary is the one sketch 041 introduced (`.sq` with `data-tone`) and is reused for
every page. Because more than one view now uses it, it is promoted to one shared documented name,
`status-square`, instead of copying a `view-x-sq` rule five times. A square is never the only carrier
of meaning: it always sits beside a word or has an `aria-label`/`title`.

### Page-by-page tone use

- **Project page.** Decision outcome: Good `complete`, Revisit `in-flight`, Reversed `missing`, Pending `quiet`; an outcome the page cannot classify is `quiet` and its own text becomes the note. Good carries a square and no chip; the other three carry a square and a chip. Count tiles: complete `complete`, pending `quiet`, shipped before `complete`, out of scope `quiet`.
- **Windows.** Lead chip: "0 open" `complete`; "N open" `in-flight`. Open row `in-flight`; waived row `quiet` (dashed) with its reason; fixed row `complete`. Window kinds (`unrun-verify`, `deviation`, any other string verbatim) are `quiet` chips.
- **Review ledger.** Severity: critical `missing`, warning `in-flight`, info `quiet` (the REVIEW page's own mapping, sketch 022 C). Disposition groups: open `in-flight`, deferred `quiet`, skipped `quiet` (dashed, as the REVIEW page's Skipped stamp), fixed `complete`. The "fixed in <commit>, disposition not updated" mark is a `quiet` chip, deliberately not `complete`: it is a disagreement note, not a result.
- **Milestone audit.** Verdict: `passed` `complete`, `tech_debt` `in-flight`, `gaps_found` `missing`, any other or absent status `quiet` ("Verdict not stated"). Score segments: full `complete`, partial `in-flight`, zero of N `missing`. Gap groups: an empty group reads "No gaps" in `complete`; a non-empty group is `missing`. Tech debt rows `in-flight`, advisory/deferred/skipped-by-design items `quiet`. Nyquist chips `complete` / `in-flight` / `missing` / `quiet` by compliant / partial / not validated / missing.
- **Coverage.** INTEGRATE `complete`, OPT-OUT `quiet`; any other decision text `quiet` verbatim. Nothing on this page is `missing`: an opt-out is a reasoned decision, not an absence.
- **Shipped mark.** `complete`.

### Accent reserved for, in this phase's new UI, exactly these

1. The `.eyebrow` kind label on the project page and each new page (existing rule reused verbatim).
2. The project page core-value card's 3px top rule (sketch 041 B).
3. `complete`-tone marks as listed above: Good decision squares and the complete count tile, the "Shipped v1.0" chip, the windows "0 open" lead chip and fixed squares, the audit passed verdict, full score segments and "No gaps" line, coverage INTEGRATE squares, the ledger's fixed squares. They share the existing `complete` styling; nothing is tinted by hand.
4. The archived-milestone arrival highlight: the target block's `--primary-tint` background and 2px `--primary` left rule (`data-target="true"`), present until the user navigates away.
5. The keyboard focus ring (`--ring` is `--primary`, already global).

Expected density: on every page except the project page, accent shows as the eyebrow plus a handful of `complete` squares or chips, well under a tenth of the visible area. On the project page the Good decision squares are the densest accent: on Labelore's own PROJECT.md roughly two thirds of 27 decisions are Good, so about 18 spine squares plus 18 jump-strip squares are filled `--primary`. This is justified because the squares are 0.6rem and 0.85rem marks on a mostly `--background` page (area stays well under 10%), the sketch was approved with them, and each carries a word or `aria-label`, so the accent marks a state and never decorates. The 10% rule binds area, not count.

Not accent: links (`.text-link` / `.source-link` as they stand), the pressed ledger tab (the `secondary` button variant), chips other than `complete`, severity pips, headings, numerals, the spine rail, the count tiles' borders, the jump-strip hover outline (`--foreground`).

Focal point per page: project page, the core-value card (accent top rule) beside the project name; windows, the lead count; review ledger, the open-of-total number in the shared head; audit, the verdict chip; coverage, the integrated-versus-opted-out split.

The page keeps the same shape whether or not anything is open: lead, then Open, then Waived, then Fixed history, with an empty group shown as one `empty-note` line ("Nothing open." / "Nothing waived.").
2. **Open and Waived**, one section each, rows grouped by phase (group head: phase label in `Label`, then a count; groups in the order phases first appear; `quick/260727-3mo`-style values are shown verbatim). A row: `status-square`, the id in mono (`#8`), a `quiet` kind chip, the description (Body, clamped to 3 lines with "Read more" `text-link` when longer), then Meta: file path in mono (`file:line`, line omitted when empty, end-ellipsis, full value in `title`) and "Recorded {date}". A waived row adds the **reason** beneath in a left-ruled note (3px `--muted-foreground` rule on `--card`, the TODO note-card treatment) labelled "Waived because"; a waived row with no reason shows the dashed `quiet` line "No reason recorded".
3. **Fixed history**: one `<details>` per phase (`history-*` family), all collapsed, summary "{phase} · {n} fixed" with a trailing count; the body lists the rows as above with the resolved date. When there are none the section is omitted (the lead already says it).
4. **Source of truth (planner picks per CONTEXT).** Read the fenced JSON block first, then the table, then the frontmatter counts. If the counts in the frontmatter disagree with the rows actually listed, show a `notice` (plain, no `destructive`) above the lead: "This file's counts disagree with its rows: it says {a} open, the ledger lists {b}. The rows are shown." The two numbers are never merged.
5. Unknown kinds and statuses render verbatim as `quiet`; a row with no phase groups under "No phase".

### 4. Review ledger (REVIEW, REVIEW-DISPOSITION, REVIEW-FIX; analogs: review threads 022, plan pair page)

Routes (Phase 7 D-06): `/{project}/phase-N/review`, `.../review-disposition`, `.../review-fix`, plus the
quick-task and archived-phase equivalents; each opens the same page on its own tab. The page uses
`ArtifactHeader`, then:

1. **Tab strip, only when a second file exists (D-11).** A `nav` (`aria-label="Review files"`) of `Link`s styled as `PairSwitch` is: Review, Disposition, Fix, with the pressed tab `aria-current="page"` (`secondary` variant, others `ghost`). A tab appears only for a file that exists; no disabled or "missing" tab. With a lone REVIEW the page is byte-for-byte today's review page: no strip, no shared head. Several fix files are one "Fix" tab. A tab's trailing count is the number of findings that file speaks to, in Label size.
2. **Shared head (appears with the strip).** The open-of-total number: open count in the lead number style over "of {total} findings" (Meta). Beside it one row per severity present, in this order: critical, warning, info. Each row: the severity pip (the existing `view-review-sev`), the severity word, "{open} of {total} open", and a segmented bar of `status-square`s (one per finding, filled for fixed, otherwise by severity tone). A severity with no findings is omitted. Totals are over the REVIEW findings; if there is no REVIEW file, over the disposition's findings, else the fix files'.
   - **Open comes from the disposition (D-08).** A finding the disposition leaves `open` is counted open even when a fix file says fixed. With no disposition file the head shows no open count: it shows the total and "{n} fixed in the fix report" only, and the REVIEW tab keeps its existing outcome tally logic.
   - **The disagreement mark (D-08).** Where a fix file says a finding was fixed and the disposition still says `open`, the finding carries a `quiet` chip "Fixed in {commit}, disposition not updated" (commit as a 7-character mono hash, full value in `title`), wherever the finding appears (Review thread header, Disposition Open group, Fix section). The two signals are never merged: the head counts it as open, and the head's muted line says "{n} open here are marked fixed in the fix report" when n > 0.
3. **Review tab**: the existing review threads page, unchanged, below the head.
4. **Disposition tab (D-10).** Groups in this fixed order, an empty group omitted: **Open** (`in-flight`), **Deferred** (`quiet`), **Skipped** (`quiet`, dashed square), **Fixed** (`complete`). Group head: `status-square`, name (Label), count. Each row: severity pip with the finding id, the finding title, and then Meta: for Deferred and Skipped the **reason** in full (never clamped to less than 3 lines; "Read more" beyond that); for Fixed the commit (mono, taken from the fix file where one exists, else "Commit not recorded" in `quiet`). Unknown disposition values go to a final "Other" group with their value shown verbatim.
5. **Fix tab (D-09).** One section per fix file, each an `<section id="fix-{suffix}">` with a labelled heading: the suffix title-cased ("Backend", "Frontend"), muted file name in mono beside it; a single unsuffixed file has no section heading. Section lead: its own status/counts from frontmatter ("2 fixed, 0 skipped" and the fixed-at date). Rows grouped Fixed, Skipped, Deferred; each row: finding id pip, title, files modified as mono chips (capped at 3 then "+N"), commit (mono), and for Skipped/Deferred the reason. Shared head totals across every fix file. The tab link opens at the first section; a section anchor is shareable.
5a. A fix file whose body lists no entries still gets its section and lead, and under it one `empty-note` line: "No fixes listed for this file."
6. A finding id that appears in one file and not the others still shows on its own tab; a fix-file entry with an id the review does not hold is listed under a final "Not in the review" `quiet` group.
7. Live phases, archived phases and quick tasks follow the same rules.

### 5. Milestone audit (analog: verification board 021)

Route: the audit's own file address under its milestone (`/{project}/v2.0/audit`; planner confirms against the route table). Cover, then ledgers:

1. **Cover.** `.eyebrow` "Milestone audit", `h1` "{milestone_name or milestone}" (falls back to the title, then the file name), meta row: the **verdict chip** (large: `--fs-7`, weight 600; text "Passed" / "Tech debt only" / "Gaps found" / the raw status verbatim; "Verdict not stated" `quiet` when absent) and "Audited {date}". The verdict is the first thing on the page.
2. **Scores.** A row of tiles, one per key under `scores` in the author's order (`requirements`, `phases`, `integration`, `flows`, any other verbatim): label, then `34/34` in the lead number style, then a segmented bar (one segment per unit when the denominator is at most 24, otherwise a proportional bar). Values `n/m`, `{n: , m:}`, a percentage or a bare number are all accepted; a value the page cannot read is shown verbatim as text with no bar. No `scores` key: the row is omitted (silent).
3. **Gaps.** Three groups in this order, from `gaps` frontmatter (`requirements`, `integration`, `flows`; any other key appended): each a head with `status-square`, name and count. Empty reads **"No gaps"** in the `complete` tone, one line, never a blank section. A gap row: id in mono (extracted when the text starts with one), the gap statement, and its **evidence** (Meta, muted, clamped to 3 lines with "Read more"); an object-shaped gap prints its known fields (`id`, `description`, `evidence`, `status`) and shows unknown fields as a labelled `dl`.
4. **Tech debt by phase.** One group per `tech_debt` entry, in file order: head = phase (verbatim, with the mono phase number split from its slug when it has one) and "{n} items". Rows: an extracted leading id (`INT-W1`, `WR-03`, `IN-01`, `AUTH-06`) as a mono chip, an extracted status word in parentheses (`deferred`, `open`, `advisory`, `skipped by design`) as a `quiet` chip, then the text (Body, clamped to 3 lines, "Read more" in place). `cross-phase (integration)` and `planning-docs` are valid group names and render verbatim. A total ("{n} items across {m} phases") sits in the section head.
5. **Nyquist** (when present): one chip row, "Compliant {list}", "Partial {list}", "Not validated {list}", "Missing {list}", chips in the tones above; an empty list is omitted.
6. **Narrative.** Everything the page did not claim from frontmatter renders below as the existing `artifact-document` body in a folded `<details>` (`artifact-metadata`-style disclosure) titled "Audit narrative"; prose sections fill any field the frontmatter lacks (CONTEXT recommendation: frontmatter first, prose second). The old fixture shape (prose only) therefore shows its narrative open by default, with no scores row, "Verdict not stated" if no status, and no empty section scaffolding.

### 6. Archived copies and the "Shipped" mark (D-02)

- The target block opens (`<details open>`), takes `data-target="true"` (`--primary-tint` background plus a 2px `--primary` left rule), and carries a **Shipped mark**: a `status-chip` `data-tone="complete"` reading "Shipped v1.0 · 10 Sep 2026" (date from the milestone's ship line/MILESTONES.md; "Shipped v1.0" alone when no date). The mark also sits on the block when the user reaches it by ordinary navigation, so the same block never looks different by route; only the highlight is arrival-only.
- No filtered mode and no archived file page. A milestone with no History block (an archive file whose milestone the roadmap does not list) falls back to the generic document view with its existing notice.

### 7. Coverage page (analog: a plain matrix)

Route: the phase `coverage` address (Phase 7 grammar). `ArtifactHeader` eyebrow "API coverage", `h1` from the file's H1 (else "API coverage").

- **One-line file (D-14, the normal case).** A single quiet card (`quiet-state`: `Plug` or `Unplug` lucide icon, `--primary`-tinted icon per the shared rule) reading **"No external API in this phase"**, with the file's reason underneath in Meta ("phase manages local/SMB project folders, markers, and audit rows — no third-party service surface"; text after the first colon or the whole sentence when there is none). No matrix, no counts.
- **Matrix file.** Shown only when the file holds a table with a capability column and a decision column. Head: "{n} integrated, {m} opted out" with a two-segment bar (`complete` / `quiet`). The file's lead lines (scope, surfaces, the "Full coverage by default" note) render above as a quiet caption block (`source-note`, the blockquote's text). Then two groups, **Integrated** then **Opted out**; a row: `status-square`, capability (mono, wraps), decision chip (`complete` "Integrate" / `quiet` "Opt out"), reason (Meta; an opt-out with no reason shows the dashed `quiet` line "No reason given"). ### 9. Accessibility

- Heading structure: one `h1` per page (project name; "Broken windows ledger"; milestone name; the review page keeps its existing title; coverage title); sections are `h2`; ledger group heads are `h3`. Chips and squares are never headings.
- The tab strip is navigation, not an ARIA tablist: links with `aria-current="page"`, like `PairSwitch`; arrow-key tab switching is not added.
- Spine rows and the jump strip are real `<button>`s with accessible names that include the outcome; the spine is an `<ol>` so the order is announced. The jump strip is a `role="group"` labelled "Every decision in order".
- Disclosure rows (spine, "Read more", fixed history) use `aria-expanded`; "Show every reason" uses `aria-pressed`.
- Squares are `aria-hidden` when a word sits beside them; otherwise they have `role="img"` and an `aria-label`. Tone is never carried by colour alone.
- Count tiles are links; their accessible name is "{n} {label} {sub-line}".
- Live regions: none needed (nothing updates on a timer).
- Contrast: every new text colour is an existing token already validated in both themes; `--muted-foreground` on `--card-veil` is the masthead's weakest pair and is checked in the screenshot review.
- `prefers-reduced-motion`: nothing animates, so nothing to disable.
- Narrow widths (390px): the masthead, strip, ledger heads and margin stack as described per page; no horizontal page scroll; mono paths end-ellipsise with full text in `title`.
