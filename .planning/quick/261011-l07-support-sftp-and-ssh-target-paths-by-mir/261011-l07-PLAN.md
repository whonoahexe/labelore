<verified_facts>
These were checked on this machine on 2026-10-11 (read-only probes only):
- `ssh -T -o BatchMode=yes rhgpu.taile250fc.ts.net …` works non-interactively. Connection setup takes about 2.4 s. The remote login shell is /bin/bash. The remote `.planning` is 2.0 MB (a 1.9 MB tar stream) and takes about 4–10 s end to end over Tailscale. It contains no symlinks.
- Remote exit codes pass straight through ssh: `[ -e '/nope' ] || exit 65` makes ssh exit 65. ssh exits 255 on its own failures, for example "Could not resolve hostname …".
- `ssh … -- '-oProxyCommand=…' true` is refused with "hostname contains invalid characters" (exit 255). The `--` separator stops option parsing in OpenSSH 10.5.
- Node's WHATWG URL parses `sftp://` and `ssh://` as opaque-host URLs. It gives back protocol, hostname, port, username, password and a percent-encoded pathname. It accepts `sftp://-oProxyCommand=x/y` with hostname `-oProxyCommand=x`, so the host MUST be validated separately. `sftp://h` gives pathname "". `sftp://h/~/proj` gives pathname `/~/proj`. `[::1]` keeps its brackets in hostname.
- Local GNU tar 1.35 extracts `tar -x -f - -C <dir> --no-same-owner --no-same-permissions .planning` from a `tar -cf - .planning` stream correctly (checked with fixtures/dense). os.tmpdir() is /tmp and TMPDIR is unset.
- dist/ exists, so the production smoke can serve `/`. The `--smoke` flag currently prints "Labelore smoke passed for X" whether or not the project loaded, because it only checks that loadStatus is present. Task 1 adds the status to that line so the live checks can assert it. No test or script depends on the line's exact text.
- The invalid-project screen renders LoadStatus.message verbatim under one generic heading (D-15). New messages need no UI change, and no new LoadStatus variant is wanted.
- PlanningRepository's `rootPath` argument works only as a label. It is used in load messages, `snapshot.rootPath`, `project.rootPath` and the `basename(rootPath)` fallback for the project name. Every disk read goes through the injected PlanningFilesystem, and artifact paths are root-relative. So passing the remote address as the repository's rootPath, together with a LocalFsPlanningFilesystem built on the mirror, makes the UI show the remote address. That includes the app-shell title tooltip and the projectDisplayName fallback.
- After load(), every route serves from in-memory snapshot data. The renderer reads `artifact.body`, not the disk. So an old mirror can be deleted as soon as a new snapshot is built.
</verified_facts>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| CLI argument → ssh argv | The typed address becomes the host, user, port and remote path of a local ssh process. |
| Local → remote shell | ssh hands the remote command string to the remote user's login shell (/bin/bash on the target). |
| Remote tar stream → local disk | Archive bytes produced on the remote host are unpacked into a local directory. |
| Mirror → served UI | Mirrored files are parsed and rendered exactly like local planning files (existing sanitizing pipeline). |
| Process lifecycle → local disk | Cleanup code deletes directories on the local machine. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-L07-01 | Elevation of privilege | buildMirrorCommands / parseRemoteTarget (host, user) | high | mitigate | Strict host and user character rules, which reject a leading `-`; port must be an integer 1–65535. `--` always precedes the destination. ssh and tar are spawned with argv arrays and `shell: false`. Task 2 pins `-oProxyCommand=x` and `-badhost` as invalid and the exact argv order. |
| T-L07-02 | Tampering | remote command string (path) | high | mitigate | The only remote command is a fixed template of `[ -e ]`, `[ -d ]`, `cd` and `exec tar -cf`. The one interpolated value, remoteRoot, is single-quoted by quoteForRemoteShell. Absolute or `./` roots never start with `-`, and control characters are rejected. Task 2 pins quoting of `'`, `$()`, backticks and `;`. Nothing in the template writes, so remote planning state cannot be changed (CLAUDE.md read-only constraint). |
| T-L07-03 | Tampering | local tar extraction of a remote stream | medium | mitigate | Extraction goes into a fresh mkdtemp directory (0700) with `--no-same-owner --no-same-permissions` and the `.planning` member filter. GNU tar defaults strip leading `/`, refuse `..` members, and delay creating unsafe symlinks. Every later read goes through LocalFsPlanningFilesystem's containment guard rooted at the canonicalized mirror, so a symlink pointing outside throws PathEscapeError and degrades to a read warning. |
| T-L07-04 | Tampering | removeTempDirSync | high | mitigate | Deletes only a direct child of os.tmpdir() (or its realpath) whose basename starts with the validated `labelore-remote-` prefix; anything else returns false untouched. Task 3 pins refusal of a foreign prefix, a nested path and fixtures/. |
| T-L07-05 | Spoofing | ssh host authentication | medium | mitigate | The system ssh client keeps its default host-key checking, which is never disabled. BatchMode=yes makes an unknown or changed key fail instead of prompting, and "Host key verification failed" surfaces as permission-denied with the stderr excerpt. |
| T-L07-06 | Information disclosure | address parsing, stderr in UI | low | mitigate | URLs carrying a password are rejected, and the password is redacted to `***` in rawPath and messages; there is no password auth path at all. stderr excerpts are control-stripped, capped at 400 chars, and rendered as React text, never HTML. |
| T-L07-07 | Information disclosure | mirror directory | low | mitigate | mkdtemp makes the directory 0700. It is removed on refresh swap, failed mirror, server close, exit, SIGINT and SIGTERM. A SIGKILL can leave one behind under the user's own temp dir; that is accepted, since it is the user's own data on the user's own machine. |
| T-L07-08 | Denial of service | spawnMirrorRunner | medium | mitigate | BatchMode=yes means no prompt can hang. ConnectTimeout=15. | T-L07-09 | Repudiation | remote reads | low | accept | Reads run as the user's own ssh identity and appear in the remote host's normal sshd logs. Labelore adds no audit trail, which is acceptable for a personal read-only tool. |
