# Quick 261016-2j6: Compact discussion-log table (S4) Summary

The discussion-log parser now reads a `| Question | Options | Selected |` table under a `##` heading as one question per row, so the page shows the answers instead of "0 decided".

## What changed

- `extractS4Topic`, `parseCompactRow`, and the option split and match helpers in `section-projection.ts`. `extractDiscussionLog` takes the S4 branch after S1 and S3 and before S2.
- Options are split on a slash with whitespace on both sides. Selected is matched to an option by exact match first, then by a single unambiguous prefix. `You decide` resolves to claude, `Other: ...` to custom, an empty cell to open. Selected text that names no single option appears as an unnumbered answer.
- Any other non-table line in the section (such as `**Notes:**`) keeps the topic in the page's remainder.
- S1, S2 and S3 code paths are untouched.

## Tests

- S4 parser matrix and a hostile-row timing case (100k-character Options cell, 50k-asterisk Selected cell, under 200ms) in `test/section-projection.test.ts`.
- Real reference log: 16 questions, 0 open. Topics: Chat feel & gestures 4/4, Sending photos & videos 6/6, Voice notes 3/3 (leftover), Push & onboarding 3/3.
- Full suite: 2266 passed, 3 failed. All three failures are pre-existing and unrelated: `test/token-guard.test.ts`, `test/presentation/coverage.test.ts`, and the flaky timing test in `test/security-register.test.ts`.
- `npm run typecheck` and eslint on the touched files pass.

## Deviations from Plan

- The S4 branch in `extractDiscussionLog` does not require zero `###` subsections, so a compact table next to a table-less `###` still parses; the `###` lines count as leftover. S1 still wins whenever a `###` holds a table.
- The options separator is `\s/\s` (one whitespace character per side) rather than `\s+/\s+`, to keep the scan linear on long whitespace runs. Behaviour is the same after trimming.
- Task 2 tests and implementation were committed together as one commit.
