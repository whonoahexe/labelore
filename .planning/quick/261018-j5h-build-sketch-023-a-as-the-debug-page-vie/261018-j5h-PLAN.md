<objective>
Build sketch 023's winner, **A: Case file** as refined in rounds 2–4, as the page view for GSD debug session files (`.planning/debug/*.md` and `.planning/debug/resolved/*.md`). The page leads with what matters for the session's status. While a session is open it shows where it stands: the current hypothesis and the next action. While it waits on a person it shows what to check. Once diagnosed or resolved it shows the root cause and the fix. Under that sits the trail: expected vs actual, a suspects board (confirmed, ruled out, also considered) and an evidence log you can filter. Today these files are discovered as an unrecognised kind, parsed by the generic handler and shown by the fallback view.

Purpose: debug sessions are the next type in the per-type view loop (DISCUSSION-LOG through LEARNINGS are built). GSD writes their sections in a loose YAML style (`key: value` blocks, bold-key bullets, `- timestamp:` lists, a fenced yaml reasoning checkpoint), so they must be read line by line and must degrade, never throw, across the shapes the sketch proved: resolved with three causes, awaiting a check, diagnosed only, resolved with 24 evidence entries, resolved over five rounds, and still investigating.

Output: directory-position kind routing in discovery; a server-side extractor and handler; a pure composer, the view components and one delimited CSS block, wired through the view-registry seam; one copied fixture; discovery, extractor, handler, composer, corpus and contract tests; a fixture-server helper and an e2e spec; the design-language clause; and a Playwright side-by-side against the sketch.
</objective>
