<objective>
Restructure the RESEARCH page's Summary block so it reads calmly instead of as congested walls of text. The framing paragraph becomes a calmer lead. Every later paragraph becomes a numbered finding row that you can scan.

Purpose: the user said the research summary "looks a bit congested and a bit overwhelming". Today the whole first paragraph is set at 1rem as a 9+ line lead, and the other paragraphs run together as small grey slabs (see .playwright-mcp/summary-before.png). An audit of all 13 real RESEARCH.md files and the GSD research template found the same Summary shape every time. It is 2–5 prose paragraphs followed by a Primary recommendation. Paragraph 1 is always the framing, and each later paragraph is one distinct finding. That structure is reliable enough to show off.

Lead decision (Claude's discretion, per the orchestrator's direction 1): size the lead down. Do not promote a first-sentence headline. The corpus's first sentences run about 27–60 words. They carry code spans (load()/refresh(), backend/src/auth/mod.rs), version numbers ("zip 8.6.0", "0.05rem"), quoted sentences that end in a period inside the quote, D-NN references, and trailing [VERIFIED: …] evidence tags. So a sentence cut can land inside an inline-markdown span, and even when it lands cleanly the "headline" would still be a 4–5 line display block. A calmer size and a narrower measure fix the wall without that risk.

Output: the composer model change (lead: Block[] plus numbered findings), the new Summary markup, the calm-lead and finding-row CSS, updated and new unit and corpus tests, and a design-language note.
</objective>
