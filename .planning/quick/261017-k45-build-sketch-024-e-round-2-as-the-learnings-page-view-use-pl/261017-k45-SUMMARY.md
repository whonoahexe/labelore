# Phase quick-261017-k45 Plan 01: LEARNINGS page (chapter tabs) Summary

A LEARNINGS file now opens as a retrospective: a big title, a one-sentence lede, a labelled source bar that narrows every chapter to one artifact, and tabs that show one chapter at a time with each entry's reason, sources and graduation beside it.

## What the page now shows

- **Head.** A small label row (for example "Learnings · Phase 1", "Extracted 8 Aug 2026", the project name, and the warning chip when the file has parse problems) with copy-path and View / Source on the right. Then the one big title (the file's own heading without the "Phase 1 Learnings:" lead), then the lede: "40 learnings from this phase: 14 decisions, 9 lessons, 10 patterns and 7 surprises, drawn from 10 artifacts." When the frontmatter lists missing artifacts, a dashed note says "Extracted without 05-UAT.md — learnings from it are not here."
- **Source bar.** "Where they came from · pick one to show only its learnings", one labelled segment per source with its count (shown only with two or more sources). Segments grow by count, are never narrower than their label and wrap. Picking one narrows every chapter: tab counts drop, emptied tabs are disabled, the selected tab moves to the first non-empty one, the chapter header reads "1 of 7", and a line reads "Showing the 1 learning from 01-REVIEW.md · Show all". Picking it again or Show all clears it. Nothing touches the URL.
- **Tabs.** "01 What we decided 14", "02 What we learned the hard way 9", "03 What we’ll reuse 10", "04 What surprised us 7" (only kinds present). Arrow keys, Home and End move between enabled tabs. Each entry shows its document number, title and body on the left and a side note on the right: the kind's own field first (Rationale, Context, When to use, Impact), any other labelled fields, a "From" line with each source and its note, and a "Graduated to <target>" badge (date in the tooltip).
- **Also in this file.** One chip row (Frontmatter, plus any section the page does not show); chips open that place in Source mode.
- Source mode is the plain page, as before. If a file has no parsed entry, the old promoted-section view still renders.

## What was built

- Server side: `extractLearningsRetro` reads both shapes GSD writes (headed entries and plain list items, with a trailing "(D-NN)" moved into the source) in one fenced-aware line scan with caps; `LearningsHandler` puts the result in `structured.learnings` together with the phase from the path, the quick id and the file's scope. Registered after the UI-SPEC handler so it comes before the frontmatter-only and generic handlers. The dense golden changed only by that key on its six LEARNINGS entries.
- Browser side: a pure composer (head, lede, chapters, source bar, Also chips, filter helpers) and a view, wired through a `learningsRetro` manifest hook and one early return in the artifact page (no kind branch).
- One delimited CSS block after the UAT block; a design-language clause recording the kind colours.

## Decisions as built (plain language)

- **The project-level LEARNINGS.md shares this page.** It already resolves to the same kind, GSD writes it in the same four-section shape, and the sketch rendered it on purpose ("Learnings · Project", "from this project"). Keeping it on the old view would have needed a per-file branch the view system forbids. A milestone-stamped `vX.Y-LEARNINGS.md` is not claimed and keeps the old view.
- **Own head, no breadcrumb row or metadata disclosure in View mode**, like the SUMMARY and REVIEW pages; the Frontmatter chip leads to Source where the metadata sits.
- **Title** keeps the author's capitalisation ("Portal-Owned Identity & Sessions").
- **Kind colours are identity marks, not tones**: decision primary, lesson in-flight, pattern foreground, surprise missing; used only on the tab underline and number and the chapter rule and number. No `data-tone` is written, the parse-degradation tones never appear, corners stay squared, and there is no added motion (hover is a colour change).
- **Empty bodies:** an entry that goes straight from its title to a labelled field shows the title alone, with the field in the side note.
- An entry with no field, no source and no graduation renders no side note, and its text spans the row.

## Deviations from the sketch (kept, all corrections)

- Titles keep the file's real heading instead of the sketch's humanised folder name ("Portal-Owned Identity & Sessions", "Per-Type Document Views", "Identity Slice"). At 1440px the longer sp01 title wraps to two lines inside the 20-character measure.
- Lede singulars and nouns: "1 decision, 1 lesson and 1 pattern" (sketch said "1 decisions"), "1 surprise", "1 learning", and "drawn from 2 sources" for D-NN references (sketch said "artifacts").
- Empty-body entries no longer repeat the labelled field as a body (sketch did; 7 in the synthetic file, 2 in studio-portal phase 1).
- Date reads "21 Sep 2026" (the app's own formatter), not the sketch's "21 Sept 2026".
- The sketch's "Synthetic" chip, variant nav, toolbar, shell header, per-entry Copy button and toast are not built (sketch-only).
- A bare list entry has no empty side note (the sketch drew an empty one).
