The user asked for three things on the CONTEXT page (verbatim): "in the context view page, figure out a way to add 'canonical references' and 'existing code insights'. also, i noticed '⚠️ Requirement amendments this discussion forces' in phase 2's context page. figure out a way to showcase that too. just make sure these 3 things dont draw attention"

Requirement IDs for this quick task:
- 3OB-01: Recognise requirement amendments (the `<blocking_amendments>` tag, or a heading matching /requirement amendments?/i after any leading emoji). Show them as a quiet collapsed row labelled with the emoji-stripped heading, not as an unrecognised "extra" section.
- 3OB-02: Canonical references appear in View mode as a quiet collapsed row, grouped by their ### titles.
- 3OB-03: Existing code insights appear in View mode as a quiet collapsed row, grouped by their ### titles.
- 3OB-04: Low emphasis. Only existing neutral tokens; no --primary, no tone, no card, no hero stat; collapsed by default.
- 3OB-05: C-1 holds. Nothing is dropped, absent sections render nothing, older payloads are tolerated, nothing throws, and the generic remainder disclosure stays removed.

Current state (verified during planning; it supersedes the orchestrator's note): commit 1d0baf3 ("drop the View-mode remainder disclosure") removed the closed "More in this document" disclosure. Canonical references and code insights are therefore not visible in View mode at all. `composeContextBrief` still computes `more`, but nothing renders it. Separately, `<blocking_amendments>` is unrecognised, so SP 02/03/04 each render it as a full `.view-context-extra` section with a ⚠️ heading before the register, and SP 02's extra also ends with a literal closing-tag line.

Design (Claude's discretion, grounded in the existing brief components):
- One quiet "back matter" strip closes the brief, after the ideas panels. It holds up to three collapsed rows, in this order: amendments (one row per section), then canonical references (merged into one row), then existing code insights (merged into one row).
- Collapsed, a row is one hairline-ruled line: a lucide chevron, the label, a bare muted count (list items plus table rows, shown only when above 0) and a one-line ellipsised hint of the ### titles.
- Expanded, a row shows its groups. Each group has a small muted title, then the existing `BlockList`, at one step smaller than the rest of the brief.
- Content is rendered from server-side structured `Block`s through `Inline`/`BlockList`, the same XSS-safe path as the rest of the brief (T-lju-01), not from group HTML. This keeps it DOM-free and unit-testable, lets the corpus word-coverage guard prove nothing is dropped, and turns D-NN mentions into the brief's muted jump buttons.
- Trade-off (accepted): `.planning/` paths render as code, without the Source-mode reference-preview popover.

Output: an extractor role and fields, a composer `asides` model, a `ContextAsides` component, CSS, tests, refreshed goldens, a design-language doc update and a restarted service.
</objective>
