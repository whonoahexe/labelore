<objective>
Build sketch 017's winner, **D: Console — rail + severity × STRIDE threat board + waiver ledger + boundary flow chips**, as the SECURITY page view. A SECURITY.md is a phase's threat contract: frontmatter (status, threats_open, asvs_level, created, sometimes block_on), a lead paragraph, Trust Boundaries, the Threat Register (sometimes grouped, sometimes without a Component column), the Accepted Risks Log (sometimes prose only), extra sections, the Security Audit Trail and Sign-Off. The view answers "is anything blocking, and where is each threat" at a glance: identity and the threats-open gauge in a sticky rail, one square per threat on a severity × STRIDE board, and the waivers, boundaries and sign-off one scroll below.

Purpose: SECURITY is the next type in the per-type view loop. Today it renders through the generic promoted-section view with a three-fact block.

Output: a server-side SECURITY extractor and handler, a pure composer, the console components and one delimited CSS block, wired through the same view-registry seam as UAT and UI-SPEC (handler → structured.security → manifest hook → artifact page); unit, corpus, contract and static-markup tests; a narrow e2e spec for post-merge; gsd-browser side-by-side evidence against the sketch with every deviation fixed or recorded.
</objective>
