# Phase quick-261023-61l Plan 01: Note page, annotated Summary

A note now opens on its own page: the first sentence as a big title, its labelled clauses one row each beside a label gutter, the todo it became (or why there is none) in a margin card, and every file it mentions one click from the clipboard.

## What the page shows

- **A quick note** (for example the crop-photos note): the eyebrow "Note", "Noted 21 Oct 2026 · 15:58", a "Now a todo" chip, copy path and View / Source, then the title in large type. Under it a Lifted | As written toggle and six rows (Today, Decided · 21 Oct 2026, How, Preset constraint, Estimated, Batch), each with its label in a gutter. Decided is green-toned, Bug / Cause / Observed / Suggested are amber-toned, the rest are plain outlines. The margin holds the todo card: "Became a todo", Done, a Minor weight marker, the media area, the todo's title, "Names this note in notes:", its resolution clamped to three lines, a "Batched with" row that opens the sibling note, and "Open todo ↗". Under it, "Mentions · 1" lists the file; clicking it (or the reference in the text) copies the path, highlights every place it appears and says "Copied" for about a second and a half. As written shows the note as one paragraph. The page ends with one "Also in this file" row; Frontmatter opens Source.
- **A one-line note** (the tariff tooltips note): the whole note is the display-size title, "That’s the whole note — one line." sits under it, there is no toggle and no Mentions. Its card says it was promoted word for word into a pending P2 todo.
- **A promoted note with no todo behind it** (the back-button and download-cap notes): a dashed card reads "Promoted, but untraced". The download-cap note also shows its five code identifiers as plain monospace text, not as file mentions.
- **A note that was not promoted**: the Not promoted chip is quiet, and the card reads "Still a note — Not promoted to a todo."
- **An explore note** (the per-kind rendering note, the milestone brief): it reads as a document with its title, its `context` as a lede, the body as the app renders it with the leading H1 dropped, and a margin with "In this note · 6" (each entry jumps to its heading with no animation) followed by the related todo cards. No toggle and no Mentions.
- Labelore's own sketches note shows the correction below: title "Show sketches inside Labelore instead of a separate file server.", then a "Then" row, Want, two Open questions, Today and Suggested interim, beside the P2 todo it became, with three mentioned files.

## Decisions as built

- **Notes get their own kind from where they sit.** A markdown file whose first folder under `.planning/` is `notes` is kind `note`, at any depth. Its location stays `other`, so the tree, search grouping and goldens did not move. A `notes.md` inside a phase folder is untouched. The discovery test that used to pin `notes/n.md` as unrecognised now says `note` (the one existing assertion this item had to change).
- **The todo lookup reuses the TODO page's relation.** I imported the shared index from `src/presentation/todo-notes.ts` (`buildTodoNoteIndex`, `todosOf` and `notesOf`) and wrote no second relation. Its rules already match the plan (promoted beats listed beats wiki link beats mentioned; a `[[slug]]` for a missing note links nothing; a `notes:` entry for a missing note adds no batched row), so no fix in the sibling module was needed and the TODO page's files are unchanged. The join's signature follows the TODO page's join (`presentation, registry, bodyOf, notePath`) rather than the plan's corpus-object sketch, so note bodies come from the same artifact-index lookup. Weight levels use the todo handler's `levelOf` (the same word table as the dashboard's `severityOf`); the weight marker colours are the TODO page's, written under the note view's own `view-note-weight` names. The literal date reader is local to the composer because 61k's date helper follows time zones, which a note's wall-clock time should not.
- **A quick note's title is its first sentence**, not the whole lead clause as the sketch had it. The sentence splitter also breaks before a backtick; the rest of a multi-sentence lead becomes a first row headed "Then". None of the eight sketch quick notes changes; labelore's sketches note is the one that does.
- **Explore or quick**: a frontmatter title or a heading outside a code fence makes an explore note (the sketch's rule, made fence-aware).
- **Reaching the page is unchanged**: dashboard Notes rows, search, the TODO page's source notes, and a batched row on another note. Listing notes in the sidebar is not built.
- **"Suggested interim" is not in-flight.** Tones apply to the whole label (as the sketch's table does), so only a label that is exactly Suggested takes the amber tone.
- The contents jump uses an instant scroll, because the app sets smooth scrolling on the whole document; a plain `scrollIntoView` animated.
- The explore body is drawn by the app's own renderer (tables, code, links), so a `[[wiki link]]` in a note shows as text there, as it does on any document page.

## Deviations from Plan

**1. [Rule 3 - Blocking] Existing discovery assertion.** The TODO page's discovery test asserted `notes/n.md` stays unrecognised, which contradicts the plan's own directory-position rule. I changed that single assertion to `note`.

**2. [Rule 1 - Bug] Narrow overflow.** The explore note overflowed at 420px (61px) because the main column's implicit grid track grew to its widest content. Fixed with a `minmax(0, 1fr)` track.

**3. [Rule 1 - Bug] Token guard.** The first CSS pass used em-based sizes and a rem padding that the token guard names; replaced with tokens (the mono reference inside the display title inherits the title size).

**4. Plan grouping.** The contents list, explore-note rendering and the CSS for both shapes were written with the Task 1 page, so the second commit holds the explore-note composer tests, the corpus guard, the view contract and the design-language record. The fixture project lives in `test/fixtures/notes` as the plan says, even though the TODO page's fixtures hold copies of the same notes.

**5. Join signature.** See the relation decision above.
