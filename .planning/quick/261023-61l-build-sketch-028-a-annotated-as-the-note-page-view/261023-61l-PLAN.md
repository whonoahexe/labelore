<objective>
Build sketch 028's winner, **A: Annotated**, as the page view for GSD notes (`.planning/notes/*.md`). A quick note (`/gsd-note`: a date, `promoted`, one paragraph kept word for word) becomes a page. Its first sentence is the title. The labelled clauses ("Decided:", "Bug:", "Want:", "Off limits:", …) follow in reading order, one row each, with the label in a gutter and a Lifted | As written toggle. The margin holds the todo the note became (with any notes batched into it) and every file the note mentions. An explore note (`/gsd-explore`: title, date, context, a full document) renders as a document with a contents list in the margin. Today notes are discovered as an unrecognised kind, parsed by the generic handler and shown by the fallback view.

Purpose: notes are the next type in the per-type view loop, built beside the TODO page (261023-61k, which shows a todo's source notes). A note never records which todo it became (only `promoted: true`), so this page looks the relation up the other way, from the todos, through the same relation the TODO page uses.

Output: directory-position kind routing; a server-side lifting extractor and handler; a server-side note-to-todo join on the document response; a pure composer, the view components and one delimited CSS block, wired through the view-registry seam; a fixture project rebuilt from the sketch data; discovery, extractor, handler, join, composer, corpus, agreement and contract tests; a fixture-server helper and an e2e spec; the design-language clause; and a Playwright side-by-side against the sketch.
</objective>
