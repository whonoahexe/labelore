# Sketch 013: PATTERNS page

## Design Question
A PATTERNS.md (pattern map) is 300–980 lines, mostly code excerpts for the planner. The human
questions are: when was it mapped, how much of this phase has a precedent to copy, which files are
new ground and why, what each file copies from (and any warning about copying it), and which house
rules apply. Classification, assignments and no-analog each list the same files, so every variant
merges them into one file map — each file once, with its match quality, analog, guidance, reason and
the rules that apply.

## How to View
http://cinedise:4174/013-patterns-page/

Toolbar **Doc**: sp v1.0/02 (hard — 26 rows, 11 new ground, grouped classification, mapper's note,
divergence warning, planner notes), sp P4 (assignments grouped by concern, not per file), sp P1,
labelore 05 (clean; header says 17/17 while No Analog Found lists 3).

## Shared across variants (not the question)
- Cover: eyebrow "Pattern map · Phase N", title, facts (Mapped · Files analyzed · Analogs found, as
  the author wrote them), a match-quality meter derived from the classification, and a one-line
  **Searched** scope in quiet mono that truncates with a "more" toggle.
- Mapper's note (the preamble before the first section) as a flagged notice.
- Back matter: extra sections (e.g. Cross-Cutting Notes for the Planner) collapsed; an
  "In the source only" strip (code excerpts, line citations, data-flow labels, metadata).
- Tones: exact → complete, role-match → quiet, partial → in-flight, no analog → missing.

## Variants
- **A: Lanes by match** — four lanes (Exact · Role match · Partial · New ground), 5 per lane + show
  more; a file expands in place to its analog, guidance, no-analog reason and rule chips. House rules
  as cards below; "Show N files" lights those files across the lanes.
- **B: By location + panel** — the file map grouped by area (the doc's own groups when it has them),
  one row per file with a quality chip and "← analog"; a sticky side panel shows the selected file.
  House rules as a chip strip that dims the files a rule does not touch.
- **C: Copies from** — organised by what to copy: New ground cards with reasons first, then each
  existing template with the new files that copy it, then files extended in place, then rules.

## What to Look For
- sp v1.0/02: do 11 new-ground files and the divergence warning on collector.rs stand out enough?
- Does the scope line stay quiet enough?
- sp P4: assignments are per concern, not per file — which variant still reads?
- Which answers "how risky is this phase?" fastest, and which answers "what do I copy for X?"

## Data note
data.js is generated by gen-data.mjs from the real files (a parse feasibility check as well).
Guidance keeps prose only; code excerpts are counted. Rule-to-file links come from backticked paths
in **Apply to**; rules without paths show as "applies broadly".

## Winner
**B: By location + panel.** Build it. The cover stays as shared (Mapped · Files analyzed · Analogs
found, match-quality meter, quiet Searched line, mapper's note). One file map grouped by area — the
doc's own classification groups when present, else by path — one row per file with a quality chip,
name + dir, and "← analog" / "↺ extends itself" / "no analog". A sticky side panel (stacks below on
narrow widths) shows the selected file: quality, copy-from, why nothing matches, guidance with
"More guidance", rule chips, excerpt count. House rules as a chip strip above the map; picking one
explains the rule and dims the files it doesn't apply to. Planner notes collapsed in back matter;
code excerpts, line citations and data-flow labels left to Source mode.
