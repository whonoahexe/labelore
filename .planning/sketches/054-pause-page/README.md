# Sketch 054: Pause page

## Design Question
Phase 11 D-05..D-08 (VIEW-17). `/gsd-pause-work` writes `.planning/HANDOFF.json` and a `.continue-here.md`
together; whether they share one page or get two linked pages is this sketch's call (D-05). Either way: where work
stopped (task N of M), the single next action, human actions pending with blocking ones first, what is left, the
long context notes folded; the date and age always (D-08) with a quiet "work has moved on since" when
STATE/ROADMAP show the phase complete; a nested `.continue-here.md` opens the same layout headed with its context
(D-07); where the files disagree both values show, never merged.

Real shape (generated by running the pause-work steps on a scratch copy, read for shape only):
- HANDOFF.json: `version, timestamp, phase, phase_name, phase_dir, plan (can be null), task, total_tasks, status,
  completed_tasks[] (done with commit, or in_progress with progress), remaining_tasks[], blockers[] (type
  human_action | technical | external, workaround), async_jobs[], human_actions_pending[] (action, context,
  blocking), decisions[], uncommitted_files[] (porcelain lines), next_action, context_notes`.
- .continue-here.md: frontmatter `context, phase, task, total_tasks, status (in_progress | blocked |
  almost_done), last_updated`; a BLOCKING CONSTRAINTS checkbox list; a Critical Anti-Patterns table with severity
  blocking | advisory; tag sections current_state, completed_work, remaining_work, decisions_made, blockers,
  context, next_action ("Start with: …"); Required Reading, Infrastructure State, Pre-Execution Critique Required.
- Seen for real: the detect step put `.continue-here.md` in the folder of the newest PLAN (phase 10) while both
  files named phase 11; the two `status` values differed (`paused` / `blocked`). The existing `shapes` fixture has
  an older HANDOFF layout (`paused_at`, no task lists), which the page must also read.

## Shared across all three
- Header: crumbs Lendshed / {Phase N | Spike id} / Paused work; eyebrow "Paused work · {context}"; h1 the phase
  name (or spike name); lead "Paused in {context}, {date} · N days ago"; the dashed "Work has moved on since: {what}
  ({source}, {date})" note when it applies; copy buttons per file; "No .continue-here.md beside it" / "No
  HANDOFF.json".
- Disagreements: a dashed "{field} · HANDOFF.json ≠ {field} · .continue-here.md" block per field (task, status).
- Next action: one boxed sentence at heading size with its source tag; continue-here's wording below it when it
  differs.
- Tones: done `complete`, stopped-at task `in-flight`, left `quiet`; blocking human action / constraint /
  anti-pattern `missing`; not blocking / advisory `quiet`. Never `destructive`.
- Back matter, closed bars with the file each came from: Blockers, Decisions, Uncommitted files (porcelain as
  written), Context notes, then every continue-here section.

## Variants
- **A: Task track (one page).** The plan's tasks as a row of cells (name, commit, progress), a black "Stopped here ·
  task N of M" pin, and a dashed pin where continue-here names a different task. Then the disagreements, the next
  action, and two columns: "Before you resume" (blocking actions, constraints, blocking anti-patterns) and "Can wait".
  Under 48rem the track becomes a list with the pin inline.
- **B: Two linked pages.** A pair switch at the top, each half its own URL (`/lendshed/paused/handoff`,
  `/lendshed/phase-4/continue-here`); a missing file is a hatched, disabled half. The HANDOFF page is a board:
  Waiting on you (blocking first) · Done · Stopped here · Left, with counts. The continue-here page is the note: next
  action as the lead, "Read before anything else" with tickable constraints (reading aid only, never written), then
  its sections.
- **C: Gate path (one page).** A vertical path: Behind you (done tasks) → Stopped here (task, progress,
  disagreements) → one gate bar per blocking item ("Gate 1 of 4 · Human action", each can be marked as read) →
  "Resume here, after N gates" with the next action → Ahead (tasks left). Non-blocking and advisory items branch off
  to the side.

## What to Look For
- One page or two: does B's split make the pair clearer, or make you click to see what blocks you?
- Which picture answers "can I pick this up now, and where?" fastest: the track (A), the board (B) or the path (C)?
- Do the task 3 / task 4 and paused / blocked disagreements read as facts about the files?
- Stale: does "Work has moved on since" read as a quiet fact, not an alarm?
- Nested: with only task numbers and no HANDOFF, does the page still feel complete?

## Open points for the build
- Age is computed from HANDOFF `timestamp` (older files: `paused_at`), else continue-here `last_updated`.
- "Moved on" reads the named phase's status from ROADMAP/STATE; for a spike, its manifest verdict (no example yet).
- Constraint lines split on " — " into name, what and mitigation; a line that does not split shows whole.
- A `.continue-here.md` in another phase's folder than its `phase:` frontmatter: the frontmatter wins for the head,
  the folder shows in the file path (seen for real).
- Sketch words, not UI-SPEC copy: "Paused work", "Stopped here", "Before you resume", "Can wait", "Waiting on
  you", "Work has moved on since", "Gate N of M", "Resume here", "Behind you", "Ahead", "Mark as read".

All text is made up. The repository is public.

## Winner
**C: Gate path**, chosen by the user: "C seems alright". One page for both files (settles D-05). No synthesis.

Build C as drawn in its tab (marked "★ Selected"):
- **Head** as shared above: context, date and age, the "Work has moved on since" note, a copy button per file.
- **The path**, top to bottom on one rail:
  - **Behind you:** the done tasks as small chips (id, name, commit).
  - **Stopped here:** "task N of M · {status}", the task name and its progress, then the disagreement blocks.
  - **Gates:** one gate bar per blocking item, in the order blocking human actions, blocking constraints, blocking
    anti-patterns. Each shows "Gate i of n · {kind}", what, why, its source tag, and a "Mark as read" toggle, which
    is view state only and never written to the file.
  - **Resume here:** "Resume here, after N gates · next action", the boxed sentence, and continue-here's own
    wording when it differs.
  - **Ahead:** the tasks left as dashed chips.
- **Side notes:** non-blocking human actions ("Can wait") and advisory anti-patterns branch off the path beside the
  stop and the first gate.
- **No gates:** one cleared gate reading "No gates: nothing blocks resuming".
- **Below the path:** "The rest of the handoff", the closed bars, each tagged with its file.
- **Under 52rem:** two columns (rail and body); the side notes drop under their stop.
