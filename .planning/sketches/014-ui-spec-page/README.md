# Sketch 014: UI-SPEC page

## Design Question
A UI-SPEC (UI design contract) is 100–870 lines: a design-system table, spacing, typography and
colour tables, a copywriting contract, 30–104 UI-consideration rows (flat, or grouped per element
E1…E15), registry safety, checker sign-off, and often phase-specific contracts (Layout, Motion,
Security-Critical Interaction, Revision chapters). The questions a person has are: when was it
written and is it signed off? What does the design system actually look like? Which UI states still
need a person? What does the UI say? Where do components come from?

table, 8 spacing steps including clamp()), sp P1 (security contract chapters), fixture (draft, all
checks not run, only 1 spacing step and 1 type role).

## Shared across variants (not the question)
- Cover: path, eyebrow "UI design contract · Phase N", title from the slug, **Created** date and a
  Status chip. Then a quiet mono line, "shadcn · preset b3Dqcuo4na" (or "No shadcn · preset none"),
  and the checker sign-off as one chip per dimension (✓ PASS → complete, ⚑ FLAG → in-flight, ✗
  BLOCK → missing, ○ not run → quiet, dashed). Clicking a chip opens that dimension's note. After
  that, the approval sentence, folded checker's notes, and the scope note clamped to 2 lines.
- 03 Copy deck: every copywriting row as a card with the exact string quoted, notes clamped.
- 04 Phase-specific contracts: any other `##` section, folded, with a one-line preview and a
  revision tag when the title carries one.
- 05 Registry safety: one row per registry, with block names as code, and the gate as a chip
  (in-flight only when a vetting gate is required).
- Back matter: collapsed "Agent notes" (generator tagline, the lift-rule blockquote, and the
  status-vocabulary comment) plus an "In the source only" strip.
- Colour swatches paint the document's own stated values. A token with no value gets a hatched
  "Value not in doc" swatch. A `never --primary` note becomes a Never chip, not a swatch.

## Variants
- **A: Specimen + matrix.** Spacing is a to-scale staircase plus rulers (fluid clamp values dashed
  out to their max). Type is a live sample for each role at its declared size, weight and line
  height. Colour is a 60/30/10 bar painted with the doc's values, plus a card per role with
  swatches and its "Reserved for" list. UI considerations are an element × state matrix (8
  categories), with a "Needs a person" chip row above it. Click a square to read the resolution.
- **B: Compact + attention first.** The design system is one card with three rows: spacing as a
  tick ruler, type as "Aa" at each size, colour as chips. Usage folds out per row. UI
  considerations open on the backstop and unresolved cards first, then covered states per element
  (folded, with a mini 8-state strip). Dismissed rows sit behind a toggle.
- **C: Tabbed specimen + element cards.** Spacing, Type and Colour are tabs, one at a time. Type
  is a ladder, and Colour paints a small light and dark UI mock with the doc's values, with the
  reserved-for list numbered. UI considerations are element cards, each with a labelled 8-state
  strip, and filter chips for status and state that open the matching cards.

## What to Look For
- sp v1.0/04 and labelore 02: which variant makes the 6 backstops and 9 unresolved stand out, and
  which lets you find "what happens when E6 errors?" fastest?
- sp P1 and sp v1.0/04 (token-only colour): does the hatched placeholder read as honest, or as
  broken?
- labelore 02 spacing and type (fluid clamp ranges): do the specimens still read?
- Is the shadcn/preset line quiet enough, and do the sign-off chips read at a glance?

## Data note
data.js is generated by gen-data.mjs from the real files. It also checks parse feasibility:
sign-off comes in checkbox and table forms; UI considerations come flat or as `### E#` tables, with
status spelled several ways (✅ covered, ✅ resolved *(explicit)*, N/A — dismissed, ⚠ unresolved).

## Round 2 (after feedback on round 1)
Round 1 is kept at `index-r1.html`. Feedback: the path line becomes a copy button; show shadcn and
its preset better; sign-off details go in a modal; drop the checker's notes, the phase-specific
chapters and the agent notes; highlight the design-system choices; take B's spacing, C's type, A's
colour and A's UI considerations; improve registry safety; use the RESEARCH/PATTERNS "In the
source only" strip; and the copy deck stays only if its UX earns it.

Shared in round 2: an app-style meta row ("Signed off 6/6 ⤢" chip that opens a modal like the
RESEARCH confidence one · Created · copy-path link icon · View/Source). Choice cards for component
library, icon library and font (fonts rendered in their own face), all accent-ruled. Spacing as a
tick ruler, type as a ladder, colour as the 60/30/10 bar plus role cards, and UI considerations as
the matrix. Registry safety opens with a verdict line ("No vetting needed" / "Vetting required"),
then one card per registry with the blocks grouped as New this phase and Reused. The removed
sections are listed in the "In the source only" strip.

- **A: Quiet preset, no copy.** shadcn and the preset sit in the meta row as a dashed copyable code
  chip. There is no copy section; the Copywriting Contract is listed in the source-only strip.
- **B: shadcn card, copy as UI.** shadcn is the first choice card: Initialized/Not initialized, a
  Preset locked chip, the preset as a copy field, and style/base/theme/radius. The copy section
  renders each string as the element it becomes: buttons as buttons, empty states as empty panels,
  errors as alert lines, confirmations as mini dialogs. Rows the doc describes but doesn't word,
  and rows it deliberately omits, sit in their own groups. Clicking a string copies it.
- **C: shadcn card, copy as list.** The same shadcn card. Copy is a filterable list (kind chips)
  with the element on the left and the quoted strings on the right; clicking a string copies it.

## Winner
**Round 2 synthesis: B's shadcn card + A's no copy section.** Build it, in this order:
- **Cover:** eyebrow "UI design contract · Phase N", title from the slug, then a meta row: sign-off chip
  ("Signed off 6/6" complete · "6/7 · 1 flag" in-flight · "Sign-off not run" quiet · blocked → missing),
  which opens a modal like the RESEARCH confidence dialog (each dimension with its verdict, notes only
  where written, approval at the bottom) · Created date · Status only when not approved. On the right,
  the copy-path link icon and View/Source.
- **01 Design system:** four accent-ruled choice cards. First the shadcn card (shadcn/ui or "No shadcn",
  an Initialized/Not initialized chip, a "Preset locked" chip when the doc says locked, the preset as a
  copy field, and style/base/theme/radius when the doc states them). Then component library, icon
  library, and font (each family drawn in its own face with its role). Then spacing as a tick ruler
  (fluid ranges as a bar, usage folded), typography as a ladder of live samples, and colour as the
  60/30/10 bar painted with the doc's values plus role cards (swatches with light/dark halves,
  hatched "Value not in doc", a Never chip, the reserved-for list).
- **02 UI considerations:** a coverage meter with the author's count, a "Needs a person" chip row, the
  element × state matrix (covered → complete, backstop → in-flight, unresolved → missing, dismissed →
  quiet dash), and click a square for its resolutions. "How coverage was probed" moves to the source.
- **03 Registry safety:** a verdict line (No vetting needed / Vetting required), then a card per
  registry with blocks grouped as New this phase and Reused. An empty third-party registry folds into
  the verdict.
- **In the source only** (RESEARCH/PATTERNS strip): Copywriting Contract, the phase-specific
  chapters, checker's notes, how coverage was probed, lift rule, status vocabulary, generator note,
  frontmatter.
